# AsterFiles 前期架构实施计划

## 目标

在继续扩展界面和文件操作前，先固定三条不会反复推倒的边界：

1. Windows 原始路径不会因 UTF-8 展示转换而丢失；
2. 导航和后台加载天然属于某个标签页，未来增加多标签不重写核心；
3. 本地磁盘、UNC 和未来网络位置再慢，也不能在 UI 线程执行探测或读取。

具体 FTP、SFTP、WebDAV 等协议继续后置。本阶段只建设实际需要的本地浏览闭环，不提前搭建通用网络框架。

## 必须长期保持的边界

- 文件和目录身份留在 Rust：使用 `PathBuf/OsString` 或稳定 ID。Slint 只接收展示文本和稳定 ID。
- UI 只提交意图，不调用 `is_dir`、`exists`、`read_dir`、Shell、COM 或网络 API。
- 地址栏确认后的路径候选在 Windows 后台链路规范化：补全盘符根目录、统一分隔符、兼容正斜杠 UNC、移除整条外层引号并使用系统 API 展开 %VAR%；用户的 Everything 查询原文不经过该转换。
- 每次加载携带 `TabId + RequestId`。结果只可写回对应标签页的最新请求。
- 新导航、关闭标签页和退出应用都要能取消旧任务；取消后迟到结果必须丢弃。
- `Ctrl+W` 由窗口级键盘入口统一处理，不受地址栏等 Slint 控件焦点影响；多标签时关闭活动标签并沿用相邻标签选择与任务取消规则，只剩最后一个标签时进入正常关窗流程。
- `Ctrl+T` 由窗口级键盘入口触发标签栏“+”按钮的新建标签行为；`Ctrl+N` 新建只含一个标签的独立窗口，稳定目录页沿用当前目录，设置页、加载失败页或尚无稳定目录时打开默认起始目录。新窗口不复制原窗口的其他标签、历史或选择状态，创建失败时保持原窗口不变。
- 外部文件夹路径是正式启动输入，必须保留为 Rust 原始路径；首个进程完成启动后打开该目录，后续进程优先把路径转交给已运行实例并退出；转交超时或失败时保留原始路径并正常启动当前进程，不吞掉打开请求，也不建立第二套会话或窗口协调器。单实例通信必须有明确超时和失败诊断，不得阻塞 UI 线程。
- 已运行实例接收外部路径时，以最近获得用户输入的现存主窗口为目标，新建并激活一个文件标签；不得覆盖当前标签。目标窗口在转交期间关闭时，由应用协调层重新选择仍存活的最近窗口；没有窗口时创建标准主窗口。外部导航继续生成新的 `TabId + RequestId`，并服从普通导航的取消和迟到结果拒收规则。
- “默认使用 AsterFiles 打开文件夹”属于当前用户级 Windows Shell 注册表集成，不要求管理员权限。启用时记录 AsterFiles 实际写入的键值及当前 portable 可执行文件绝对路径；关闭或恢复时只撤销仍由 AsterFiles 拥有且值未被外部改写的配置，不覆盖其他应用后来建立的选择。
- portable 可执行文件移动、改名或删除会使系统集成失效。设置页必须对照当前程序路径读取实际注册状态，区分已启用、路径失效和已被外部修改，并提供针对当前路径的重新启用及恢复 Windows 文件资源管理器入口；应用不安装后台服务，也不承诺移动后自动修复。
- `Win+E` 接管是独立的实验性 Windows 集成，不与默认文件夹打开捆绑，也不作为稳定能力。它只能通过明确开关启用，界面必须说明依赖未公开的系统行为、Windows 更新后可能失效，并提供独立恢复；实现与恢复仍遵守只修改当前用户范围、精确验证所有权和不覆盖外部改写的规则。
- 目录读取分批提交，优先让首批可见项目出现；完成前 UI 仍可导航和切换标签。
- 标签页各自保存路径、历史、列表、选择、排序、加载状态和错误；标签顺序、活动标签、关闭恢复栈和窗口布局属于窗口级状态；文件任务中心、缓存、设置和受控工作池属于应用级共享设施。
- 同窗标签排序只移动窗口级 `TabId` 顺序；不得重建 `TabSession`、取消导航/搜索/图标请求或生成新的 `RequestId`。标签拖动使用独立应用内状态机，不复用文件 OLE 拖放。
- 标签拖出创建窗口采用“目标窗口可用后才删除来源”的事务交接；保留全局 `TabId` 和完整标签状态。未完成的目录、搜索和图标请求在换窗边界取消并以新 `RequestId` 重启，已完成快照直接随标签转移；共享文件任务不随窗口复制或关闭。
- 跨窗口标签交接按目标标签栏落点插入，先确认目标窗口仍注册并完成接收，再从来源移除；取消、失焦、目标关闭和无效释放统一恢复来源。完成快照保留请求身份，未完成请求取消后在目标生成新代次。
- 单文件标签窗口允许进入同一 OLE 拖动链路。命中另一窗口标签栏时按上述事务交接；未命中来源或其他 AsterFiles 标签栏时，只以物理屏幕落点减去按下时客户区抓取偏移移动来源原生窗口。该分支不得新建窗口、转移标签、生成请求或重载页面；移动失败与系统取消必须恢复原状。
- 会话格式 ASTF8 直接保存全部窗口的布局、文件标签顺序和活动文件索引；启动时重新分配进程内全局身份并创建各原生窗口。ASTF7 及更早格式不迁移、不回退。
- Explorer 固定目录以 Windows Shell“常用位置”命名空间的后台枚举结果为唯一来源，侧栏保持 Shell 返回顺序；Shell/COM 不进入 UI 线程，不维护 AsterFiles 自有收藏或排序。
- 详细信息、列表和网格共用目录条目、选择、排序和导航身份；视图模式由应用级原始路径映射记忆，切换只改变投影，不触发目录枚举或请求代次变化。
- 文件列表直接键入默认只在当前投影中按展示名称比较前缀，命中后仍以稳定 `EntryId` 和 Rust 原始路径更新焦点、选择与滚动；用户开启“文件列表快速搜索”后，同一字母/数字入口改为当前目录范围的 Everything 地址栏搜索，首字符进入现有防抖链路，Escape 通过标签目录快照恢复选择与焦点。两种路由互斥；延迟启动必须固定 `WindowId + TabId` 并确认标签仍活动，搜索结果继续服从 `TabId + RequestId + PageSource`。
- 网格缩略图通过 Windows Shell `IShellItemImageFactory` 在后台提取，先用系统缓存、再调用系统已注册扩展；队列有限并发并以全局标签、请求代次和条目身份淘汰迟到结果，失败稳定回退类型图标。
- 2026-08-31 真实 UI 验收发现 P4 拖出/跨窗、Explorer 固定项、二维网格和缩略图投影未达到验收，并暴露 P3 外部 OLE 拖入回归；这些项目在真实复验前保持未完成。自动测试仅证明纯状态与非交互边界，不替代桌面交互验收。
- 后续截图确认标签卡片被来源客户区裁切与跨窗失败高度相关；临时预览窗口方案仍会把一次手势拆成窗口显示、轮询和第二次拖动，已删除。标签拖动改为标准 Windows OLE 拖放循环，使用进程内私有标签格式；`IDragSourceHelper` 生成跟随光标的不透明原生拖动卡片，现有各原生窗口 `IDropTarget` 同时承担标签栏命中，但文件 OLE 与标签状态仍严格分离。
- 标签 OLE 目标只提交目标 HWND 和物理屏幕落点，应用协调层再执行同窗排序、事务式跨窗移动或窗外新建窗口；Escape、释放和目标离开由同一个原生拖动循环收口，不再依赖来源窗口的移动/释放事件或全局按键轮询。网格缩略图由目录批次、进入网格、滚动及缩放共同触发可见区计划，视图切换不再承担“补发请求”的职责。
- 同窗排序与跨窗口拖入共享同一落点语义：拖动期间不移动目标窗口的现有标签，只在即将插入的位置绘制 5px 主题强调色竖条；来源窗口可隐藏来源标签但保持其余标签紧凑。`DoDragDrop` 会阻塞 Slint/winit 的绘制调度，指示器因此使用独立、无激活、鼠标穿透且不注册 `IDropTarget` 的原生工具窗口，由 OLE Hover 直接定位；离开、取消、失败、窗口关闭或成功提交后隐藏或销毁。
- 原生拖动卡片初始化会通过 `IDataObject::SetData` 写入多种 Shell 私有介质；必须保留完整 `FORMATETC` 并用系统 `CopyStgMedium` 复制介质。仅保存 `HGLOBAL` 会使 `IDragSourceHelper` 返回错误、导致标签越过阈值后立即取消。
- 用户可见文案不得散落硬编码；日期、数量和文件大小通过统一格式化入口生成。
- 多窗口文件命令在触发时固定所属 `WindowId + TabId` 与原始路径/条目快照；剪贴板、确认窗口、拖放和完成回调必须沿用该身份，后台投影不得临时改写应用级活动窗口。原生附属菜单仅在前台仍属于自身 owner 链时恢复焦点，迟到关闭事件不得激活其他主窗口。详见 [Issue #41 多窗口命令与菜单焦点复盘](postmortem/postmortem-2026-09-04-multi-window-command-focus.md)。
- 详情列表只有一份列几何状态；表头与虚拟化内容行必须共享列顺序、列宽、起点和内边距，普通目录与 Everything 搜索分别保存列顺序和列宽，横向滚动使用同一偏移同步两层。

## 侧栏分类可见性边界

侧栏的快速访问、库、磁盘、网络位置和网络分别拥有应用级可见性，新安装默认隐藏“库”。可见性持久化并投影到所有窗口，但不承担路径身份、数据加载或展开状态；隐藏分类不会改变其数据来源和加载边界。“网络位置”与“网络”保持独立，前者是已配置位置，后者是设备发现结果。侧栏分类区独立滚动，纯图标设置入口以正方形按钮固定在底部且只命中按钮自身；同行空白区域复用唯一的侧栏背景菜单入口，因此全部分类隐藏后仍可恢复。
## Issue #19 全局文字大小边界

Issue #19 将“文字大小”定义为应用级外观设置，提供小 90%、标准 100% 和大 115% 三档；选择后即时同步全部已打开的主窗口、确认窗口和文件操作窗口，新窗口继承，退出后保存。Slint 使用统一语义字号和配套布局尺寸；详情、紧凑、网格的视觉行距必须与 Rust 的滚动、可见范围、选择、框选和命中计算保持同一几何来源。改变档位不得生成标签或请求身份，不触发目录、搜索、Shell 图标或缩略图工作，也不改变原始路径、列顺序和列宽。图标、缩略图、Windows 原生菜单和窗口整体缩放不在范围内。会话正式格式直接升级，不迁移、兼容或回退旧格式。完整方案见 [Issue #19 设置外观文字大小方案](issue-19-text-size-plan.md)。
## 网络功能接入条件

只有 F0–F3 完成后才开始网络协议。接入时每个提供者必须实现同一组行为语义：连接超时、读取超时、取消、分批结果、错误分类、限并发、重试上限和断线恢复。协议实现不得进入 UI，也不得把底层阻塞调用放进 UI 线程。

## 网络位置、Windows 设备列表与 SMB 边界（Issue #10）

完整产品、架构、实施与验证方案见 [网络位置、Windows 设备列表与 SMB 实施方案](network-locations-and-smb-plan.md)。侧栏必须把“网络位置”和“网络”保持为两个独立分组：前者承载 Explorer 导入与 AsterFiles 自有的持久常用远程目标，未来可扩展到 SFTP、WebDAV 等协议；后者只显示 Windows 当前发现的局域网设备。侧栏不展开设备内部共享或文件夹；点击设备或在地址栏输入设备根后，在当前标签打开设备根，由主内容区分批显示共享并继续目录导航。设备根返回的 UNC 共享身份必须按 UNC 组件提取条目名，不能依赖本地路径的末级名称规则。侧栏内容溢出时独立滚动，窗口级文件列表滚轮仅在鼠标位于完整文件区域时接管。

首期完整支持 SMB/UNC 浏览、认证、打开、复制、移动、重命名、删除和拖放。SMB 复用 Windows 会话与凭据管理器，密码不得进入应用配置或日志。本地目录、SMB 目录、设备发现、Shell 附加信息和文件操作使用独立有界执行资源；若 Windows 阻塞调用无法通过句柄关闭或 I/O 取消在目标时间内终止，则必须使用可终止辅助进程隔离。“网络”不实现独立扫描或手动设备清单；Windows 未发现但地址已知的目标通过地址栏或网络位置访问。
## Issue #10 已交付网络边界（2026-09-04）

网络位置与 Windows 发现设备保持独立模型：Explorer NetHood 导入项每次启动在后台读取，不写入 AsterFiles 会话；自有网络位置使用 ASTF11 保存原始 `PathBuf`、名称和顺序。Windows 发现设备仍按 `WindowId + DiscoveryRequestId` 隔离请求，但保存最后一次成功结果作为下次启动的即时侧栏快照；展开分组优先显示快照，只有无快照或用户明确刷新时才重新发现，以贴近 Explorer 的稳定入口行为。点击可解析设备后，当前标签继续使用 `TabId + RequestId`，设备根通过 Windows Shell 枚举共享，UNC 共享和深层目录统一进入独立有界目录队列。本地目录监听、文件夹大小与缩略图预取不会访问 UNC。

真实 NAS 实证中，共享枚举和目录读取可完成，但把 Windows Shell 设备发现、共享枚举、目录读取与属性读取串联后，调用超过 30 秒仍未返回。因此设备发现、设备根和深层 UNC 目录读取均进入隐藏辅助进程；主进程通过 Job Object 约束其生命周期，取消立即终止，最长等待 10 秒。设备发现超时时，可从 Explorer 已保存网络位置的 UNC 目标中恢复主机列表，但不做独立扫描或维护第二份设备清单；回退入口保留 UNC 中 Windows 返回的主机大小写。网络目录按主机单并发、不同主机可并行，2 秒未返回时显示慢连接状态。网络文件操作使用独立于本地操作的串行资源域，两域可并行，冲突界面仍全局串行。映射网络盘在后台准备阶段解析为原始 UNC；当前 UNC 目录可从空白右键菜单保存为 AsterFiles 自有网络位置，自有项可从侧栏右键复制地址、排序或移除。UNC 条目的原始路径不进入主进程 Shell 图标或缩略图接口；文件只按扩展名、文件夹只按目录属性异步查询 Windows 类型图标，并与本地同类条目共享缓存，失败时使用内置通用图标。网络内容缩略图保持禁用，避免网络 Shell 扩展或内容读取拖垮应用。原生拖放注册由窗口线程内的唯一注册表拥有；单窗口关闭时按 HWND 显式注销，最后窗口关闭、活动任务取消完成或事件循环返回后的统一退出清理会先冻结注册表并一次性注销全部目标，再销毁窗口运行时，最后释放 OLE apartment。每个 HWND 最多成功注销一次；注册对象或线程本地存储的析构阶段不得调用 `RevokeDragDrop`。拖出复制不会刷新源目录，因此保留原列表位置；只有目标实际报告移动完成时才刷新源目录。侧栏内容拥有独立纵向滚动区，不参与右侧内容高度计算，文件状态栏固定在右侧列表下方。

SMB 后端可复用 Windows 会话、建立临时连接、把用户明确要求保存的凭据写入 Windows 凭据管理器，并保留凭据冲突等 Win32 错误码；连接同样通过可终止辅助进程。内容页已有账号、密码与“记住凭据”入口，凭据冲突必须由用户明确确认后才通过辅助进程断开并重新连接；认证临时文件使用 Windows DPAPI 加密。网络位置可重命名、在新标签打开、复制地址、排序、移除及打开 Windows 凭据管理器；Shell-only 导入项保留 Shell 身份并交给 Windows 打开。Issue #10 已经用户确认完成；Explorer 导入项外部修改、复制/移动/删除/回收站操作的完整辅助进程隔离，以及真实 Explorer 拖放、错误凭据和坏共享矩阵改由 [Issue #42](https://github.com/LiuYangArt/AsterFiles/issues/42) 独立跟踪。机器可读底座状态写入 `artifacts/state/network/foundation.json`，实测指标写入 `artifacts/perf/network/`。
## P2 文件操作接入边界

P2 的完整设计见 [P2 基础文件操作与右键菜单实施方案](p2-file-operations-plan.md)。文件任务中心属于应用级共享设施，使用独立 `OperationId` 和工作池，不复用标签导航的 `RequestId`，也不得占用目录读取或 Shell 图标线程。UI 只提交 `TabId + EntryId` 等意图；应用协调层在提交时解析为 Rust 原始路径快照，后台操作与 Windows Shell/COM 继续放在各自独立模块。

Issue #83 在应用级维护固定上限的文件操作撤销历史，按实际完成顺序覆盖新建文件夹、重命名、无覆盖、无合并的复制与移动，以及本地回收站删除；网络路径、永久删除、快速删除、失败、跳过和部分完成不入历史。全局 `Ctrl+Z` 只在文件列表焦点域触发，地址栏、搜索、重命名编辑器和菜单保留自身输入语义；有活动文件任务时拒绝开始撤销。撤销仍作为普通本地文件任务在后台执行并定向刷新所有相关标签。复制/移动撤销前以 Windows 强文件身份和有界目录清单确认目标未被外部修改；回收站恢复只使用 Shell 回调返回的精确 PIDL，不按名称或时间猜测。撤销复制时先把独占创建根原子隔离再复核和清理；跨盘移动及回收站恢复在提交后改写为阶段化剩余动作，允许安全重试。原路径被占用或身份无法确认时停止该项并保留为历史栈顶，绝不覆盖未知内容。

文件操作完成后发出基于原始路径的变化事件，应用协调层更新所有显示源目录或目标目录的标签；无法安全局部投影时，只为受影响标签生成新的目录 `RequestId` 并定向刷新。复制、移动、回收站删除和永久删除的取消只停止未开始工作，不回滚已经完成的项目；界面必须准确显示部分完成。右键菜单是 P2 的主要功能入口，基础文件命令进入 AsterFiles 任务中心，其他 Shell 命令通过 Windows 执行。Windows Shell 普通项和普通子菜单直接投影到可搜索快速菜单；菜单改造归入独立的 [Windows Shell 菜单集成 Feature](windows-shell-menu-feature.md)，不属于 P3。 目录空白处只有一个“新建”子菜单：自有文件夹命令保留原始目标路径并进入文件任务，Windows 模板保留 Shell 命令身份；两者共同受窗口、标签、目录请求和 Shell 子菜单代次隔离。

本地普通删除保留单次 Windows `IFileOperation` 批处理与回收站恢复语义。创建并排队 Shell 项时属于准备阶段，只报告已准备的用户所选顶层项目数；`PerformOperations` 开始后进入执行阶段，消费 Shell 当前项目回调，并并行递归统计已发现项目与字节。Shell 工作量不是文件数或字节数，只作为内部诊断信号，不直接展示给用户，也不用于推导百分比、速度或剩余时间；执行期间显示持续运动的不定进度。连续回调按约 5–10 Hz 合并，阶段切换、完成、失败和取消立即提交。批处理期间保持列表稳定，终态后按磁盘真实结果定向刷新一次。


单个目录的复制与需要实际传输的移动必须把遍历、发现和执行组织为同一条单遍增量流水线：每个条目只统计一次，首批可执行条目发现后立即开始传输，不得把完整源树统计作为复制前置条件。扫描期间“已发现文件/字节”只可单调增长，最终扫描结果与实际执行共用同一份条目来源，不能为计算总量再次递归源树。

扫描尚未结束时，总文件数和总字节数保持未知；任务中心显示“正在扫描”和已经处理的项目/字节，不显示百分比、剩余时间或由顶层任务数推算的伪进度。只有扫描到达终态后才固定可信总量并计算百分比；暂停、取消、失败和冲突等待不能把尚未完成的扫描误报为总量稳定。

连续进度达到时间门槛，并累计足够字节或文件数后提交，稳定传输时任务中心模型提交频率不超过约 5–10 Hz；低吞吐任务允许更低频，完成、失败、冲突、暂停、继续、取消和扫描终态绕过合并立即提交。暂停和取消在目录遍历、文件边界及文件块边界检查，取消必须唤醒暂停等待。

普通进度只更新任务中心中对应任务，不刷新主窗口目录模型。目标首次出现与任务终态只定向刷新确实显示受影响原始目录的窗口/标签；冲突只更新对应任务和冲突窗口，任务状态切换只更新任务中心及确有显示变化的附属窗口。任何单个进度事件都不得遍历并重建全部主窗口模型。

Issue #13 第一阶段把快速菜单请求绑定窗口、`TabId + RequestId`、原始目录和选择路径快照；UI 只接收不可执行的显示模型与稳定命令句柄，搜索只过滤已加载内存模型。专用可复用 STA worker 在同一线程创建、使用和释放 `IContextMenu`/`HMENU`，加载与调用均校验会话/请求代次，导航、切换、重复右键或关闭后的迟到结果不得更新或执行当前菜单。AsterFiles 已接管命令继续进入任务中心；动态、自绘或无法可靠投影的项目记录明确诊断，不再保留重复的完整经典菜单入口。普通子菜单使用与 Shell command ID 分离的应用内 token，在所属 STA 会话内按层发送 `WM_INITMENUPOPUP` 并读取；每层携带独立请求代次，UI 只执行叶子项的原始 command ID。Issue #13 已按用户确认范围完成；目录空白菜单的 `windows.share` 因真实 UI 投影为空而暂时隐藏，独立由 [Issue #23](https://github.com/LiuYangArt/AsterFiles/issues/23) 跟踪，文件夹对象菜单不受影响。

Issue #50 将同一套快速菜单扩展到侧栏对象：路径、Library 与 Windows 网络位置只从 Rust 模型中的原始路径或 Shell identity 解析，界面文字与行索引不承担执行身份。侧栏请求额外绑定窗口、活动标签导航代次、节点稳定标识和对应侧栏模型代次；节点刷新/消失、切换标签、重复右键或关窗后，迟到的 Shell 结果与自有命令均失效。侧栏使用对象菜单而非目录背景菜单，Shell/COM 仍只在既有 STA worker 中运行。

Issue #21 将上述快速菜单的承载层改为所属主窗的无边框工具弹窗，业务模型与 Shell 生命周期不变。根菜单和递归子菜单以独立窗口链承载，窗口链绑定 `WindowId + TabId + RequestId` 及会话、分支代次；异步结果不得通过遍历窗口猜测目标。定位只使用物理屏幕点和目标显示器 `rcWork`，支持负坐标、左右/上下翻转、限高滚动与运行中重定位。附属窗创建即带 owner 与 popup/tool-window 样式，并以 DWM cloak 覆盖首帧合成边界；子菜单按深度复用 HWND，同层切换只替换身份、内容和位置，浅层切换失效后代。附属窗不进入任务栏或 Alt+Tab、不全局置顶；外部失焦、Escape、导航失效和 owner 销毁统一关闭整条链，附属窗获焦引起的 owner 失焦不算外部失焦。
Issue #24 在此边界上增加每窗口短期展示快照和当前上下文预热：缓存键完整包含窗口、标签、导航代次与原始目录/选择，缓存行在新 Shell 会话就绪前变暗且完全不可执行；顶层使用骨架原位替换，顺序固定为自有命令、单分隔线、Windows 命令，外框可随真实行数改变且不增加 Windows 区域内部滚动。STA worker 在同一线程有界保留多个会话，预热、窗口和正在执行的菜单不再互相覆盖；PowerShell 7 背景级联通过严格限定的注册结构直接预载并安全执行，不再进入 300ms 动态等待。代码、自动验证和真实 UI 验收均已完成，Issue 已收尾。

## P3 Windows 拖放接入边界

双向文件拖放的完整设计见 [P3 Windows 文件拖放实施方案](p3-windows-drag-drop-plan.md)。拖入 AsterFiles 的真实文件系统对象只产生用户意图和原始路径快照，复制、移动、冲突、取消和进度继续由 P2 窗口级 `OperationManager` 执行；不得建立第二套文件操作引擎。拖出到 Explorer 时，AsterFiles 只提供标准 Shell 数据对象和允许效果，最终复制、移动或创建快捷方式由目标应用执行。

OLE 的 `IDataObject`、`IDropSource`、`IDropTarget`、窗口注册和拖放循环集中在 `platform/windows/drag_drop`。COM 对象遵守 STA 与窗口线程亲和，UI 不枚举目录、读取元数据或执行磁盘操作。拖动开始时由应用协调层把 `TabId + EntryId` 固定为原始路径快照；拖入任务沿用独立 `OperationId`，拖放不得复用导航 `RequestId`。操作后的路径变化继续广播给所有相关标签，外部目标无法返回可靠结果时只定向刷新，不猜测或伪造移动成功。

P3.D0 已完成：winit 自带的固定 COPY 文件目标在窗口属性阶段关闭，AsterFiles 在首个原生窗口事件到达、真实 HWND 可用后，于同一 winit/STA 线程初始化 OLE 并注册自有 `IDropTarget`，生命周期覆盖 `ui.run()`，退出严格执行 `RevokeDragDrop`、释放目标、`OleUninitialize`。底座记录进入、移动、离开、放下与撤销事件，并由后续 D1 扩展为 `CF_HDROP` 接收和文件任务提交。确定性状态写入 `artifacts/state/drag-drop/foundation.json`。

P3.D1 已完成当前目录目标：原生 STA 回调只读取 `CF_HDROP` 数据对象、当前协调层路径快照和修饰键，协商同卷移动/跨卷复制并投递原始路径意图；磁盘存在性、目标目录和路径保护在后台线程预检查，UI 线程只把已验证条目提交给既有 `OperationManager`。当前目标随活动文件标签的最近成功目录更新；设置页、加载中或错误页没有可放下目标。文件夹行目标、应用内拖放和边缘滚动仍归 D2。

P3.D2 已完成：协调层把当前可见的目录行按窗口物理坐标投影为短生命周期目标快照，原生回调只在快照内命中，不读取磁盘；文件夹目标通过稳定 `EntryId` 对应的原始路径展示悬停反馈。拖动接近列表上下边缘时每个受控周期只滚动一小段，不自动进入目录。应用内拖动在超过最小距离后，使用当前选择的原始路径快照投递到同一 D1 预检查与 `OperationManager` 链路；自身、同目录和自身子目录继续明确拒绝。

P3.D3–D5 已完成自动化实现：拖出使用标准 `IDataObject + IDropSource + DoDragDrop`，提供 `CF_HDROP`、Preferred/Performed DropEffect 和原始多选路径，外部目标完成后只保守刷新源目录。拖入链接效果在后台创建 `.lnk` 并采用 Windows 风格递增名称；系统默认拖动光标承担复制、移动、链接和禁止反馈。目录监听使用独立 `ReadDirectoryChangesW` 后台 guard，按当前文件标签动态启停、合并短时事件并定向刷新。目录枚举按 Windows 隐藏/系统属性应用独立持久化开关，会话格式直接升级为 ASTF7。

P3 右键拖放补充已完成自动化实现：右键放下只保存原始路径、目标、落点和来源允许效果，并显示独立的复制、移动、创建快捷方式或取消菜单；用户选择后重新执行路径保护和后台预检查，再复用 P2 OperationManager。菜单外点击、Escape、窗口失焦、遮挡或销毁只清除待选择状态。AsterFiles 拖出到 Explorer 时仍完全由目标决定右键拖放菜单，未修改独立 Windows Shell 菜单 Feature。

文件任务完成反馈继续复用定向刷新链路：工作线程只上报按提交顺序去重的成功最终目标，排除失败、跳过、源路径及已存在的目录合并根；每个目标标签的待选集合绑定其刷新 RequestId 和原始目录，完成后一次性多选、稳定聚焦最后一项并确保可见。重命名外部点击先提交并消费该次点击，非法名称与磁盘失败保留编辑态、输入内容和可见原因。

刷新提交仍沿用既有的选择清理语义，避免普通点击、Ctrl 多选和 Shift 连选被目录监听刷新重新带回旧状态；仅当存在与本次 `RequestId + 原始目录` 匹配的操作完成待选集合时，才在刷新提交清理之后一次性恢复新目标的选中、焦点和锚点。 列表按下只建立拖动候选快照，不再提前改变选择；未跨过拖动阈值时，唯一的选择变更仍由点击回调依据普通、Ctrl 或 Shift 语义完成。

真实互操作回归修复要求应用内拖动越过阈值后，先结束 Slint 指针捕获再进入 OLE 循环，使同一 HWND 的 IDropTarget 能收到回落事件；拖出数据同时提供 CF_HDROP、标准 Shell IDList Array 和效果格式，Explorer 据此提供复制、移动和创建快捷方式菜单。
P3 产品决策汇总见 [P3 Windows 原生集成决策摘要](p3-windows-integration-decisions.md)。Windows 隐藏文件和系统文件使用独立持久化开关：默认显示隐藏文件、不显示系统文件，显示时不使用弱化样式。系统缩略图整体移到 P4，与详细信息、列表、网格和大图标视图统一设计；P3 继续使用现有 Shell 图标链路。右键菜单与拖放、目录监听及路径边界没有实施依赖，P3 不修改菜单；菜单后续设计见 [Windows Shell 菜单集成 Feature](windows-shell-menu-feature.md)。

## Everything 平台边界（2026-08-30）

Everything 适配统一位于 `platform/windows/everything.rs`，不分发 SDK DLL。搜索、状态、分页和排序使用官方 WM_COPYDATA Query2；文件夹大小使用 Everything 1.5 的 Everything3 命名管道命令 18，直接按完整 UTF-8 原始路径读取索引值。两条官方 IPC 通道严格分工，大小不再通过搜索结果间接推导。

Everything 使用后台工作线程和 Query2 专用消息窗口，不占目录、Shell 图标或文件操作线程，也不在 Slint UI 线程执行 IPC、进程、路径或索引操作。命名管道只连接已保存实例，跨请求复用；断线后当前请求最多受控重连一次。搜索批次按 `TabId + RequestId + PageSource` 接受，文件夹大小另校验 `EntryId + 原始路径`；所有读写均有有限超时并在超时后取消。UNC 导航仍由目录工作池负责，未索引 UNC 不解析、不计算大小、不递归回退。
Issue #14 将设置入口明确整理为“连接配置、连接状态与操作、使用说明”三层。程序路径支持通过系统文件选择器选取 `Everything64.exe`；文件选择、路径检查、进程启动、IPC 与有限状态轮询继续通过应用协调层和 Windows 平台层在后台完成，不进入 UI 线程。`1.5a` 明确作为 Everything 实例名而非版本号，配置变化会失效旧验证状态。连接测试与启动必须即时显示进行中状态，并把版本、实例、数据库、文件夹大小索引及失败处理建议映射为完整中英文用户文案。页面同时说明搜索与文件夹大小的依赖边界、后台运行与索引要求，以及普通目录和 UNC 导航不依赖 Everything、未索引位置不递归回退、AsterFiles 不修改索引配置。

## Issue #44 Windows Libraries 边界

Windows Library 是 Shell 管理的虚拟容器，不能伪装为普通目录交给 `std::fs::read_dir`，也不解析 `.library-ms` XML 作为主实现。库枚举、固定状态、名称、顺序、图标、来源目录和默认保存目录均以 `FOLDERID_Libraries`、`IShellLibrary`、`IShellItem` 等 Windows Shell 接口为准，并集中在 `src/platform/windows` 的后台链路。库文件路径或 Shell parsing name 是稳定身份；展示名称不得反向用于打开、选择或文件操作。文件列表空白处的 Windows 背景菜单同样以该原始 Shell parsing name 创建，不能退化为默认保存目录、任一来源路径或 `.library-ms` 展示路径；Shell 返回的默认保存目录只可作为 PowerShell 等需要物理工作目录的命令参数。菜单请求继续按窗口、标签和导航代次拒绝迟到结果，失败必须清除加载占位并记录日志。

侧栏的库列表属于应用级异步状态，使用独立加载代次同步投影到所有窗口；Explorer 创建、修改、删除、重命名和固定状态变化只触发受控重新枚举，迟到结果不得恢复旧列表。点击库后，当前标签保存库身份并继续使用 `TabId + RequestId` 加载；库的多个真实来源分批合并，并强制按 Shell 来源顺序分组。组头使用 Shell 来源显示名和真实路径，稳定 Shell 身份只用于内部区分；每个条目始终保留来源目录下的原始 `PathBuf` 和稳定 `EntryId`，同名来源与同名条目不得合并或覆盖。来源分组同时用于列表、网格、命中和选择，普通“分组依据”不在库页面叠加第二层。刷新、组内排序、选择、搜索、历史、标签关闭和退出沿用普通目录的请求取消与迟到结果拒收规则。

空库是成功的空结果。单个来源离线、不存在、无权访问或读取失败时记录分来源错误并继续显示其他可用来源；只有没有可用结果时才投影整体错误。新建、粘贴等需要写入目标的操作只使用 Shell 返回的默认保存目录，不回退到第一个来源；没有可用默认保存目录时返回独立、可本地化的明确错误。库枚举和聚合读取使用独立受控后台资源，不得阻塞 UI、本地目录、网络目录或其他标签。确定性自动验证使用内存夹具证明映射、过滤、合并、身份、默认保存、取消、迟到结果和错误分类；真实 Explorer 同步、Shell 图标和 100%/125%/150% DPI 只由用户手动验收。

## Issue #15–#16 侧栏交互与磁盘状态边界

Issue #15 继续以 Windows Shell“主页/快速访问”固定项作为唯一数据源，不建立 AsterFiles 私有收藏、迁移或排序。pin、unpin、外部变更监听和重新枚举集中在 Windows 平台后台链路；完成结果按应用级侧栏加载代次提交到所有窗口，迟到结果不得恢复旧状态。文件列表和地址栏图标的拖入必须投递独立 `QuickAccessPin` 意图，不能复用文件复制、移动、快捷方式或 `OperationManager`。文件列表仍由稳定 `EntryId` 解析原始路径；地址栏拖动直接快照活动标签的原始成功目录。

### Issue #60 Windows 原生文件复制（2026-09-07）

Windows 单文件复制统一由 `platform/windows` 的 `CopyFile2` 适配层执行；目录遍历、冲突选择、任务进度和跨卷移动继续由文件操作层负责。每个文件先复制到目标目录内唯一的 `.asterfiles-copy` 临时项，完整成功后再提交；覆盖时旧目标在提交事务中保留至新文件就位，失败和取消不得破坏正式目标。

普通本地复制使用系统缓存模式；SMB 请求压缩传输，并仅对明确的短暂网络错误进行进程存续期内有上限的重试。暂停通过 CopyFile2 的恢复头在同一源和同一临时目标上继续，取消清理临时项。稀疏复制请求使用 Windows 11 22H2 起明确支持的原生标志；CopyFile2 保留的修改时间、文件属性、扩展属性和 NTFS 备用数据流不再由应用重新实现。符号链接继续由独立分支复制链接本身，目录遍历不跟随链接或重解析点。

同盘移动仍优先原子改名；跨卷移动仅在目标提交后删除源。若目标已完成但源删除失败，必须以独立终态准确报告，后续重试不能盲目再次复制。SMB 系统调用无限阻塞仍由 #42 的辅助进程隔离解决，本层不宣称可终止这类调用。
