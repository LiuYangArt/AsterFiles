# AsterFiles 前期架构实施计划

## 目标

在继续扩展界面和文件操作前，先固定三条不会反复推倒的边界：

1. Windows 原始路径不会因 UTF-8 展示转换而丢失；
2. 导航和后台加载天然属于某个标签页，未来增加多标签不重写核心；
3. 本地磁盘、UNC 和未来网络位置再慢，也不能在 UI 线程执行探测或读取。

具体 FTP、SFTP、WebDAV 等协议继续后置。本阶段只建设实际需要的本地浏览闭环，不提前搭建通用网络框架。

## 必须长期保持的边界

- 文件和目录身份留在 Rust：使用 `PathBuf/OsString` 或稳定 ID。Slint 只接收展示文本和稳定 ID。
- UI 只提交意图，不调用 `is_dir`、`exists`、`read_dir`、Shell、COM 或网络 API。
- 地址栏确认后的路径候选在 Windows 后台链路规范化：补全盘符根目录、统一分隔符、兼容正斜杠 UNC、移除整条外层引号并使用系统 API 展开 %VAR%；用户的 Everything 查询原文不经过该转换。
- 每次加载携带 `TabId + RequestId`。结果只可写回对应标签页的最新请求。
- 新导航、关闭标签页和退出应用都要能取消旧任务；取消后迟到结果必须丢弃。
- 目录读取分批提交，优先让首批可见项目出现；完成前 UI 仍可导航和切换标签。
- 标签页各自保存路径、历史、列表、选择、排序、加载状态和错误；标签顺序、活动标签、关闭恢复栈和窗口布局属于窗口级状态；文件任务中心、缓存、设置和受控工作池属于应用级共享设施。
- 同窗标签排序只移动窗口级 `TabId` 顺序；不得重建 `TabSession`、取消导航/搜索/图标请求或生成新的 `RequestId`。标签拖动使用独立应用内状态机，不复用文件 OLE 拖放。
- 标签拖出创建窗口采用“目标窗口可用后才删除来源”的事务交接；保留全局 `TabId` 和完整标签状态。未完成的目录、搜索和图标请求在换窗边界取消并以新 `RequestId` 重启，已完成快照直接随标签转移；共享文件任务不随窗口复制或关闭。
- 跨窗口标签交接按目标标签栏落点插入，先确认目标窗口仍注册并完成接收，再从来源移除；取消、失焦、目标关闭和无效释放统一恢复来源。完成快照保留请求身份，未完成请求取消后在目标生成新代次。
- 单文件标签窗口允许进入同一 OLE 拖动链路。命中另一窗口标签栏时按上述事务交接；未命中来源或其他 AsterFiles 标签栏时，只以物理屏幕落点减去按下时客户区抓取偏移移动来源原生窗口。该分支不得新建窗口、转移标签、生成请求或重载页面；移动失败与系统取消必须恢复原状。
- 会话格式 ASTF8 直接保存全部窗口的布局、文件标签顺序和活动文件索引；启动时重新分配进程内全局身份并创建各原生窗口。ASTF7 及更早格式不迁移、不回退。
- Explorer 固定目录以 Windows Shell“常用位置”命名空间的后台枚举结果为唯一来源，侧栏保持 Shell 返回顺序；Shell/COM 不进入 UI 线程，不维护 AsterFiles 自有收藏或排序。
- 详细信息、列表和网格共用目录条目、选择、排序和导航身份；视图模式由应用级原始路径映射记忆，切换只改变投影，不触发目录枚举或请求代次变化。
- 网格缩略图通过 Windows Shell `IShellItemImageFactory` 在后台提取，先用系统缓存、再调用系统已注册扩展；队列有限并发并以全局标签、请求代次和条目身份淘汰迟到结果，失败稳定回退类型图标。
- 2026-08-31 真实 UI 验收发现 P4 拖出/跨窗、Explorer 固定项、二维网格和缩略图投影未达到验收，并暴露 P3 外部 OLE 拖入回归；这些项目在真实复验前保持未完成。自动测试仅证明纯状态与非交互边界，不替代桌面交互验收。
- 后续截图确认标签卡片被来源客户区裁切与跨窗失败高度相关；临时预览窗口方案仍会把一次手势拆成窗口显示、轮询和第二次拖动，已删除。标签拖动改为标准 Windows OLE 拖放循环，使用进程内私有标签格式；`IDragSourceHelper` 生成跟随光标的不透明原生拖动卡片，现有各原生窗口 `IDropTarget` 同时承担标签栏命中，但文件 OLE 与标签状态仍严格分离。
- 标签 OLE 目标只提交目标 HWND 和物理屏幕落点，应用协调层再执行同窗排序、事务式跨窗移动或窗外新建窗口；Escape、释放和目标离开由同一个原生拖动循环收口，不再依赖来源窗口的移动/释放事件或全局按键轮询。网格缩略图由目录批次、进入网格、滚动及缩放共同触发可见区计划，视图切换不再承担“补发请求”的职责。
- 同窗排序与跨窗口拖入共享同一落点语义：拖动期间不移动目标窗口的现有标签，只在即将插入的位置绘制 5px 主题强调色竖条；来源窗口可隐藏来源标签但保持其余标签紧凑。`DoDragDrop` 会阻塞 Slint/winit 的绘制调度，指示器因此使用独立、无激活、鼠标穿透且不注册 `IDropTarget` 的原生工具窗口，由 OLE Hover 直接定位；离开、取消、失败、窗口关闭或成功提交后隐藏或销毁。
- 原生拖动卡片初始化会通过 `IDataObject::SetData` 写入多种 Shell 私有介质；必须保留完整 `FORMATETC` 并用系统 `CopyStgMedium` 复制介质。仅保存 `HGLOBAL` 会使 `IDragSourceHelper` 返回错误、导致标签越过阈值后立即取消。
- 用户可见文案不得散落硬编码；日期、数量和文件大小通过统一格式化入口生成。
- 详情列表只有一份列几何状态；表头与虚拟化内容行必须共享列顺序、列宽、起点和内边距，普通目录与 Everything 搜索分别保存列顺序和列宽，横向滚动使用同一偏移同步两层。

## 实施切片

### F0：请求身份与过期结果隔离

- [x] 引入 `TabId`、`RequestId` 和单标签 `TabSession`。
- [x] 删除 UI 回调中的同步路径探测，所有验证进入后台任务。
- [x] 后台结果带请求身份；新导航发出后，旧结果不能覆盖当前页面。
- [x] 失败导航保留上次成功列表和路径，并展示可恢复错误。
- [x] 为请求代次、过期结果和失败保留旧状态增加测试。

验收：连续提交快、慢、无效路径时，窗口保持响应，最终只显示最后一次有效请求的结果。

### F1：无损路径与稳定条目 ID

- [x] `FileEntry` 保存原始文件名和原始路径；展示名称单独生成。
- [x] Slint 行模型删除可执行的字符串路径，改用稳定 `EntryId`。
- [x] 打开、重命名和后续文件操作通过 ID 找回原始路径。
- [x] 覆盖简繁中文、日文、韩文、Emoji、组合字符和不能无损转成 UTF-8 的 Windows 名称。

验收：展示替代字符不会改变真实操作目标；显示文本不能被当作文件身份。

### F2：可取消的分批加载

- [x] 目录任务支持取消，并在枚举和元数据读取之间检查取消状态。
- [x] 条目按批次提交，完成时再提交最终状态；排序策略不得阻塞 UI。
- [x] 使用受控工作池，单个慢位置不能堵住全部标签页。
- [x] 定义加载中、部分结果、完成、取消、权限不足、断开和普通失败状态。
- [x] 记录首批结果时间、取消延迟和被丢弃的过期结果。

验收：UNC/断开映射盘或人工慢任务不会冻结 UI，也不会阻塞其他标签页加载。

### F3：多标签页

- [x] 窗口维护标签顺序、活动标签和关闭恢复栈。
- [x] 新建、切换、关闭和恢复标签；每个标签保留独立历史和页面状态。
- [x] 切换时立即显示该标签上次成功内容，后台刷新不影响其他标签。
- [x] 会话恢复只保存稳定、明确的数据，不序列化运行中的任务。

验收：任一标签加载、失败或断开时，其他标签仍可正常浏览。

### F4：本地化基础

- [x] 建立语言资源入口，先提供简体中文和英文。
- [x] 迁移按钮、列名、状态、错误、文件类型和相对时间等所有用户文案。
- [x] 定义缺失翻译行为；增加资源完整性检查。
- [x] 验证 Windows UI 正文字体及中文回退，图标字体不得承担正文；P1 负责迁移到统一字体样式并做全页面与高 DPI 检查。

验收：运行时切换中英文后界面文案完整，中文和混合文字不乱码、不截断关键操作。

## 网络功能接入条件

只有 F0–F3 完成后才开始网络协议。接入时每个提供者必须实现同一组行为语义：连接超时、读取超时、取消、分批结果、错误分类、限并发、重试上限和断线恢复。协议实现不得进入 UI，也不得把底层阻塞调用放进 UI 线程。

## P2 文件操作接入边界

P2 的完整设计见 [P2 基础文件操作与右键菜单实施方案](p2-file-operations-plan.md)。文件任务中心属于应用级共享设施，使用独立 `OperationId` 和工作池，不复用标签导航的 `RequestId`，也不得占用目录读取或 Shell 图标线程。UI 只提交 `TabId + EntryId` 等意图；应用协调层在提交时解析为 Rust 原始路径快照，后台操作与 Windows Shell/COM 继续放在各自独立模块。

文件操作完成后发出基于原始路径的变化事件，应用协调层更新所有显示源目录或目标目录的标签；无法安全局部投影时，只为受影响标签生成新的目录 `RequestId` 并定向刷新。复制、移动、回收站删除和永久删除的取消只停止未开始工作，不回滚已经完成的项目；界面必须准确显示部分完成。右键菜单是 P2 的主要功能入口，基础文件命令进入 AsterFiles 任务中心，其他 Shell 命令通过 Windows 执行。现有“显示完整经典菜单”保持为兼容入口；后续菜单改造归入独立的 [Windows Shell 菜单集成 Feature](windows-shell-menu-feature.md)，不属于 P3。

## P3 Windows 拖放接入边界

双向文件拖放的完整设计见 [P3 Windows 文件拖放实施方案](p3-windows-drag-drop-plan.md)。拖入 AsterFiles 的真实文件系统对象只产生用户意图和原始路径快照，复制、移动、冲突、取消和进度继续由 P2 窗口级 `OperationManager` 执行；不得建立第二套文件操作引擎。拖出到 Explorer 时，AsterFiles 只提供标准 Shell 数据对象和允许效果，最终复制、移动或创建快捷方式由目标应用执行。

OLE 的 `IDataObject`、`IDropSource`、`IDropTarget`、窗口注册和拖放循环集中在 `platform/windows/drag_drop`。COM 对象遵守 STA 与窗口线程亲和，UI 不枚举目录、读取元数据或执行磁盘操作。拖动开始时由应用协调层把 `TabId + EntryId` 固定为原始路径快照；拖入任务沿用独立 `OperationId`，拖放不得复用导航 `RequestId`。操作后的路径变化继续广播给所有相关标签，外部目标无法返回可靠结果时只定向刷新，不猜测或伪造移动成功。

P3.D0 已完成：winit 自带的固定 COPY 文件目标在窗口属性阶段关闭，AsterFiles 在首个原生窗口事件到达、真实 HWND 可用后，于同一 winit/STA 线程初始化 OLE 并注册自有 `IDropTarget`，生命周期覆盖 `ui.run()`，退出严格执行 `RevokeDragDrop`、释放目标、`OleUninitialize`。底座记录进入、移动、离开、放下与撤销事件，并由后续 D1 扩展为 `CF_HDROP` 接收和文件任务提交。确定性状态写入 `artifacts/state/drag-drop/foundation.json`。

P3.D1 已完成当前目录目标：原生 STA 回调只读取 `CF_HDROP` 数据对象、当前协调层路径快照和修饰键，协商同卷移动/跨卷复制并投递原始路径意图；磁盘存在性、目标目录和路径保护在后台线程预检查，UI 线程只把已验证条目提交给既有 `OperationManager`。当前目标随活动文件标签的最近成功目录更新；设置页、加载中或错误页没有可放下目标。文件夹行目标、应用内拖放和边缘滚动仍归 D2。

P3.D2 已完成：协调层把当前可见的目录行按窗口物理坐标投影为短生命周期目标快照，原生回调只在快照内命中，不读取磁盘；文件夹目标通过稳定 `EntryId` 对应的原始路径展示悬停反馈。拖动接近列表上下边缘时每个受控周期只滚动一小段，不自动进入目录。应用内拖动在超过最小距离后，使用当前选择的原始路径快照投递到同一 D1 预检查与 `OperationManager` 链路；自身、同目录和自身子目录继续明确拒绝。

P3.D3–D5 已完成自动化实现：拖出使用标准 `IDataObject + IDropSource + DoDragDrop`，提供 `CF_HDROP`、Preferred/Performed DropEffect 和原始多选路径，外部目标完成后只保守刷新源目录。拖入链接效果在后台创建 `.lnk` 并采用 Windows 风格递增名称；系统默认拖动光标承担复制、移动、链接和禁止反馈。目录监听使用独立 `ReadDirectoryChangesW` 后台 guard，按当前文件标签动态启停、合并短时事件并定向刷新。目录枚举按 Windows 隐藏/系统属性应用独立持久化开关，会话格式直接升级为 ASTF7。

P3 右键拖放补充已完成自动化实现：右键放下只保存原始路径、目标、落点和来源允许效果，并显示独立的复制、移动、创建快捷方式或取消菜单；用户选择后重新执行路径保护和后台预检查，再复用 P2 OperationManager。菜单外点击、Escape、窗口失焦、遮挡或销毁只清除待选择状态。AsterFiles 拖出到 Explorer 时仍完全由目标决定右键拖放菜单，未修改独立 Windows Shell 菜单 Feature。

文件任务完成反馈继续复用定向刷新链路：工作线程只上报按提交顺序去重的成功最终目标，排除失败、跳过、源路径及已存在的目录合并根；每个目标标签的待选集合绑定其刷新 RequestId 和原始目录，完成后一次性多选、稳定聚焦最后一项并确保可见。重命名外部点击先提交并消费该次点击，非法名称与磁盘失败保留编辑态、输入内容和可见原因。

刷新提交仍沿用既有的选择清理语义，避免普通点击、Ctrl 多选和 Shift 连选被目录监听刷新重新带回旧状态；仅当存在与本次 `RequestId + 原始目录` 匹配的操作完成待选集合时，才在刷新提交清理之后一次性恢复新目标的选中、焦点和锚点。 列表按下只建立拖动候选快照，不再提前改变选择；未跨过拖动阈值时，唯一的选择变更仍由点击回调依据普通、Ctrl 或 Shift 语义完成。

真实互操作回归修复要求应用内拖动越过阈值后，先结束 Slint 指针捕获再进入 OLE 循环，使同一 HWND 的 IDropTarget 能收到回落事件；拖出数据同时提供 CF_HDROP、标准 Shell IDList Array 和效果格式，Explorer 据此提供复制、移动和创建快捷方式菜单。
P3 产品决策汇总见 [P3 Windows 原生集成决策摘要](p3-windows-integration-decisions.md)。Windows 隐藏文件和系统文件使用独立持久化开关：默认显示隐藏文件、不显示系统文件，显示时不使用弱化样式。系统缩略图整体移到 P4，与详细信息、列表、网格和大图标视图统一设计；P3 继续使用现有 Shell 图标链路。右键菜单与拖放、目录监听及路径边界没有实施依赖，P3 不修改菜单；菜单后续设计见 [Windows Shell 菜单集成 Feature](windows-shell-menu-feature.md)。

## Everything 平台边界（2026-08-30）

Everything 适配统一位于 `platform/windows/everything.rs`，不分发 SDK DLL。搜索、状态、分页和排序使用官方 WM_COPYDATA Query2；文件夹大小使用 Everything 1.5 的 Everything3 命名管道命令 18，直接按完整 UTF-8 原始路径读取索引值。两条官方 IPC 通道严格分工，大小不再通过搜索结果间接推导。

Everything 使用后台工作线程和 Query2 专用消息窗口，不占目录、Shell 图标或文件操作线程，也不在 Slint UI 线程执行 IPC、进程、路径或索引操作。命名管道只连接已保存实例，跨请求复用；断线后当前请求最多受控重连一次。搜索批次按 `TabId + RequestId + PageSource` 接受，文件夹大小另校验 `EntryId + 原始路径`；所有读写均有有限超时并在超时后取消。UNC 导航仍由目录工作池负责，未索引 UNC 不解析、不计算大小、不递归回退。

当前 E1–E3 已接入。Issue #1 将普通目录和 Everything 搜索的详情列表收敛为唯一列几何链路：表头与虚拟化内容行共享列顺序、列宽、起点、内边距和横向滚动偏移；普通/搜索分别持久化列顺序与列宽。分隔符拖动只修改当前模式的列宽，不触发搜索请求、排序或退出搜索；换序后按当前视觉相邻列调宽。会话持久化正式格式随该状态直接升级，不增加旧 ASTF 格式兼容、迁移或回退。名称命中片段高亮布局不在 Issue #1 范围内。
