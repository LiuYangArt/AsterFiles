# P2 基础文件操作与右键菜单实施方案

## 1. 目标

P2 把 AsterFiles 从只读浏览器扩展为可可靠整理本地文件的日用工具。本阶段完成新建文件夹、单项重命名、复制、剪切、粘贴、回收站删除、永久删除、冲突处理和窗口级文件任务中心。

右键菜单是这些能力的主要入口，不额外增加一排重复的文件操作按钮。菜单外观由 AsterFiles 按当前主题绘制，命令来源同时包含 AsterFiles 基础命令和 Windows 经典 Shell 菜单；其中基础文件操作统一进入 AsterFiles 文件任务系统，其他 Shell 命令仍由 Windows 执行。

正式支持 Windows 11。Windows 10 不作为开发和验收目标。

## 2. 已确认的产品决策

- 与 Windows Explorer 和其他应用共享系统剪贴板。
- 复制、移动、删除、冲突和进度由 AsterFiles 自己展示，不弹 Windows 自带复制进度窗口。
- 首版不跨应用重启恢复未完成任务。
- 关闭最后一个窗口时，如仍有复制、移动、删除或待冲突处理任务，弹窗询问是否等待完成；默认选择等待。
- 默认删除到 Windows 回收站；回收站不可用或失败时明确报错，不自动改为永久删除。
- 永久删除必须二次确认，可对大目录采用“立即从原位置移除、后台释放空间”的快速路径。
- 文件夹同名行为与 Windows Explorer 一致：合并目录，再逐项处理内部冲突；不先删除整个目标目录。
- P2 接入右键菜单完整入口。P3 继续负责 Shell 扩展隔离、超时、兼容性和异常恢复的强化，不重复建设第二套菜单。

## 3. 范围

### 3.1 P2 必须完成

- 空白处菜单：新建文件夹、粘贴，以及 Windows 提供的目录背景命令。
- 单项和多选菜单：打开、剪切、复制、重命名、删除、永久删除，以及 Windows 和第三方 Shell 扩展提供的命令。
- `Ctrl+C`、`Ctrl+X`、`Ctrl+V`、`F2`、`Delete`、`Shift+Delete`、菜单键和 `Shift+F10`。
- 本地磁盘、跨本地磁盘和 UNC/SMB 路径的文件与目录操作。
- 批量和递归复制、移动、回收站删除、永久删除。
- 冲突暂停、覆盖、跳过、保留两者和对当前任务全部应用。
- 任务进度、速度、剩余项、取消、部分完成、失败原因与失败项重试。
- 操作后更新所有显示受影响路径的标签，不无条件重载整个窗口。
- 关闭应用时的任务等待提示。

### 3.2 P2 不做

- 跨重启续传或恢复任务。
- 撤销已完成的复制、移动、重命名或删除。
- 批量重命名和操作预览；继续属于 P4。
- FTP、SFTP、WebDAV、S3 或厂商网盘。
- 自建文件回收站，或直接写入 `$Recycle.Bin` 内部结构。
- 承诺任意第三方 Shell 扩展都可稳定运行；P2 必须有原生经典菜单出口，P3 再做隔离和兼容性强化。

## 4. 用户交互

### 4.1 右键选择规则

- 右键未选中的条目：先将其设为唯一选中项，再打开菜单。
- 右键已选中的条目：保留当前多选集合。
- 右键空白处：清除选择并打开目录背景菜单。
- 菜单键或 `Shift+F10`：对焦点条目打开菜单；没有焦点条目时打开空白处菜单。
- 单项重命名只在恰好选中一个条目时启用；粘贴只在剪贴板包含可用文件列表且目标目录可写时启用。

### 4.2 菜单组成与命令路由

菜单模型只向 Slint 暴露显示文字、图标、启用状态、层级、分隔线和不可解释的命令 ID，不暴露可执行路径字符串。

基础命令由 AsterFiles 插入并接管：

- 新建文件夹；
- 剪切、复制、粘贴；
- 重命名；
- 删除到回收站；
- 永久删除。

Windows 经典菜单通过 `IContextMenu::QueryContextMenu` 取得真实命令。属性、打开方式、在终端中打开和第三方扩展通过原始 `InvokeCommand` 执行。若 Shell 同时提供复制、剪切、粘贴、重命名或删除，界面只保留 AsterFiles 接管的对应命令，避免绕过任务中心。

普通文字、图标和子菜单由 Slint 外壳呈现。无法可靠解析的动态、自绘或特殊项目进入“显示完整经典菜单”，由 Windows 原生菜单窗口承载。菜单会话必须保持底层 `IContextMenu` 与原生菜单对象存活到关闭；动态子菜单按需初始化，并处理 `IContextMenu2/3` 所需消息。

### 4.3 新建文件夹与重命名

- 新建文件夹后在当前列表中插入临时条目并进入行内命名；提交成功后替换为真实条目，失败则保留输入并显示原因。
- 重命名在文件名列行内完成；`Enter` 提交，`Escape` 取消，失去焦点时提交。
- 文件默认只选中主文件名，不选扩展名；文件夹选中完整名称。
- 名称验证遵循 Windows 规则，包括保留名称、结尾空格或点、路径分隔符和空名称。
- 仅大小写变化的重命名必须正确完成；实现不得依赖大小写不敏感比较后直接判定“无变化”。
- 所有操作通过 `EntryId` 找回原始 `PathBuf/OsString`，展示文字不承担身份。

### 4.4 剪贴板与粘贴

- 使用 Windows 文件剪贴板格式，使 AsterFiles 与 Explorer 双向复制和移动。
- 剪切状态在列表中提供弱化视觉反馈；剪贴板所有权或内容变化后立即清除旧剪切标记。
- 复制或剪切时保存原始路径快照；粘贴时重新校验源项，源项消失或已变化时按单项失败处理。
- 同一磁盘移动优先使用原子移动；跨磁盘移动按“复制成功后删除源项”处理。部分复制失败时不得删除对应源项。
- 不允许把目录复制或移动到自身或其子目录；目标等于源位置时进入冲突处理，不静默覆盖。

### 4.5 冲突处理

冲突界面展示源和目标的名称、类型、大小与修改时间，允许：

- 覆盖：文件替换文件；目录与目录执行合并；
- 跳过：保留目标，不处理当前源项；
- 保留两者：为源项生成 Windows 风格的不冲突名称；
- 取消任务。

“对全部应用”只作用于当前任务、同一冲突类别，不影响后续任务。文件与目录类型不同、目标只读、权限不足、磁盘空间不足、源位于目标子树等情况不得错误套用普通覆盖规则。

目录合并时只覆盖用户明确选择覆盖的冲突文件；目标目录中原有且源目录不存在的内容必须保留。重试默认只处理失败项和未开始项，不重复复制已成功项目。

### 4.6 删除

#### 删除到回收站

- `Delete` 和普通菜单“删除”进入 Windows 回收站。
- 使用 Windows Shell 文件操作能力以保留系统回收站语义和恢复能力，但关闭系统进度与冲突界面，由 AsterFiles 接收结果并展示任务状态。
- 网络位置、部分移动介质或系统不支持回收站的路径必须明确提示“不支持回收站删除”；不得自动永久删除。
- 删除链接、快捷方式或重解析点时只删除链接本身，不跟随删除目标内容。

#### 永久删除与大目录快速移除

- `Shift+Delete` 和菜单“永久删除”必须二次确认，确认中显示选中数量并明确不可恢复。
- 普通永久删除在后台逐项执行并报告真实进度。
- 对本地卷上的大目录，可先在同一卷内原子改名并移动到 AsterFiles 管理的待清理目录，使原路径立即消失；随后后台递归删除，空间逐步释放。
- 快速路径开始前必须确认目标与待清理目录位于同一卷，并验证目标不是卷根、工作区根、用户主目录或其他受保护宽范围目录。
- 快速移动失败时退回普通后台删除；不得为快速表现跨卷复制到待清理目录。
- 待清理目录使用难以冲突的内部名称，不能伪装成 Windows 回收站。清理失败时任务中心保留真实位置和重试入口；下次启动只扫描 AsterFiles 自己的待清理记录并提示用户，不自动删除来源不明的目录。
- 界面文案明确区分“已从原位置移除”和“磁盘空间已释放”，不能在后台清理完成前显示完全成功。

## 5. 文件任务中心

任务中心属于窗口级共享设施，不属于某个标签。建议放在窗口右上角状态入口，任务运行或失败时自动可见；点击后展开侧边浮层，不增加常驻占宽面板。

每个任务至少记录：

- 稳定 `OperationId`、类型、创建时间；
- 源路径快照、目标路径和发起标签，仅 Rust 持有原始路径；
- 总项数、已完成项、剩余项、已处理字节、总字节；
- 当前速度和估计剩余时间；
- 当前条目、冲突等待、取消请求；
- 成功项、跳过项、失败项及可读错误；
- 受影响目录集合。

状态采用明确的单向转换：

```text
排队 → 预检查 → 运行 ↔ 等待冲突 → 取消中 → 已取消/部分完成
                         └──────────→ 失败/部分完成
排队/预检查/运行 ──────────────────→ 完成
```

- “取消”针对整个任务；正在执行的系统调用若不能立即中断，先进入“取消中”，完成当前不可中断步骤后停止后续项目。
- 取消不回滚已完成结果；界面列出成功、未开始和失败/取消项。
- 失败重试创建同一任务下的新执行轮次，只包含失败项和未开始项。
- 速度使用滑动时间窗计算，避免小文件任务剧烈跳动；未知总量时显示已完成项和正在扫描，不伪造百分比。

## 6. 关闭窗口与退出

- 没有活动任务时直接退出。
- 有活动或等待冲突任务时，弹窗询问：“文件操作仍在进行，是否等待完成？”
- 操作提供“等待完成”和“取消任务并退出”，默认聚焦“等待完成”；关闭弹窗等同继续等待。
- 选择等待后窗口保持打开并展示任务中心，全部任务结束后不自动退出，避免用户误以为应用仍在关闭流程；用户可再次关闭。
- 选择取消后先请求取消，进入“取消中”；不可中断步骤结束、任务状态落定并写入日志后再退出。
- Shell 第三方命令不属于 AsterFiles 任务，无法阻止其外部进程继续运行；菜单关闭后应释放本应用持有的 COM 对象。

## 7. 架构设计

```text
Slint 菜单、行内编辑、任务中心
              ↓ 用户意图 / 只读模型
应用协调层：命令路由、选择快照、标签更新
              ↓
窗口级 OperationManager ──→ 冲突决策 / 任务事件 / 取消
              ↓
文件操作工作池
        ├─ Rust 本地文件引擎
        └─ platform/windows：剪贴板、回收站、Shell 菜单、COM
              ↓
原始 PathBuf/OsString 与 Windows 宽字符 API
```

### 7.1 模块边界

- `domain/file_operations`：任务、状态、冲突、结果和变更事件，不依赖 Slint 或 Windows API。
- `fs/file_operations`：复制、移动、重命名、新建、永久删除和取消检查。
- `platform/windows/clipboard`：Windows 文件剪贴板读写和变化通知。
- `platform/windows/file_operation`：回收站语义及必要的 Shell 文件操作封装。
- `platform/windows/context_menu`：`IContextMenu` 查询、生命周期、消息转发和调用。
- 应用协调层：把 `TabId + EntryId` 解析为原始路径快照，提交任务，并把变更事件投影到相关标签。
- Slint：只显示菜单模型、编辑状态和任务模型，不访问文件系统或 COM。

现有目录读取工作池、Shell 图标工作池和文件操作工作池分离。慢复制、慢网络共享或第三方菜单不得占住目录浏览工作线程。

### 7.2 身份、取消与并发

- 文件操作使用窗口级 `OperationId`，不能复用导航 `RequestId`。
- 每次提交固定源路径快照；多选操作不得在后台重新读取当前 UI 选择。
- 任务事件携带 `OperationId + EventSequence`，协调层只接受未结束任务的新事件。
- 首版允许一个写任务运行，其余写任务排队；这样可预测冲突顺序并避免机械磁盘争用。预检查和轻量元数据读取可受控并行。
- 取消标记必须在目录枚举、文件切换、缓冲复制和重试之间检查；不能只在整个任务结束时检查。
- COM 线程模型和对象使用范围由 Windows 适配层封装；Shell 菜单对象不得跨不兼容线程随意移动。

## 8. 受影响目录更新

文件任务不直接修改 Slint 行模型，而是发出基于原始路径的变化事件：创建、删除、移动、重命名、内容可能变化和需要重新核对。

- 应用协调层把事件广播给所有 `visible_path` 命中的标签，不仅是发起标签。
- 新建、删除、同目录重命名优先局部更新条目，并维持当前排序、焦点和选择。
- 跨目录移动同时更新源目录与目标目录。
- 批量操作按短时间窗合并事件，避免每个文件触发一次全量刷新。
- 局部状态无法证明正确、Shell 外部命令完成、或事件过多时，只定向刷新受影响目录对应的标签。
- 定向刷新继续生成新的 `RequestId`，取消该标签旧目录读取并丢弃迟到结果。
- 后续 P3 的目录变化监听复用同一变化事件入口。

## 9. Windows 与 Shell 边界

- 所有 Shell/COM 调用放在独立 Windows 适配模块，且不在 UI 线程进行磁盘工作或加载第三方扩展。
- P2 允许首次打开菜单时有“正在加载更多命令”的占位；AsterFiles 基础命令必须立即可用。
- `IContextMenu` 调用的命令可能自行修改磁盘且没有标准进度。调用后将相关目录标记为可能变化并定向刷新，但不伪装成 AsterFiles 可取消任务。
- 第三方扩展可能慢、崩溃或依赖自绘消息。P2 提供完整经典菜单出口；P3 再引入隔离进程、超时、崩溃恢复和兼容性清单。
- 管理员权限命令由 Shell 自己触发系统授权；AsterFiles 不在普通启动时整体提权。

## 10. 错误与边界规则

至少覆盖：

- 源项在任务开始前或执行中消失；
- 目标磁盘空间不足、只读、断开或权限不足；
- 文件被占用、共享冲突和防病毒软件短暂锁定；
- 路径超过传统 `MAX_PATH`、非 Unicode 可逆展示名称、尾随点和保留名称；
- 本地符号链接、junction、`.lnk` 和其他重解析点；
- UNC 断开和跨盘移动中途失败；
- 文件复制成功但源删除失败；
- 目录合并中的部分成功；
- 同一路径出现在多个标签且其中某个标签正在重新加载；
- 应用收到退出请求时任务正等待冲突。

默认原则：不跟随链接删除目标；不因回收站失败升级为永久删除；不因部分成功显示整项成功；不为兼容旧实现增加隐藏回退。

## 11. 实施切片

每个切片都从核心逻辑、后台执行、界面状态到错误处理跑通，再进入下一项。

### P2.0 规格与任务骨架

- 建立 `OperationId`、任务状态、取消、事件和受影响目录通知。
- 建立窗口级单写任务队列和 Agent 可读状态导出。
- 用可控假任务验证进度、取消、部分完成和退出提示。

### P2.1 单项新建与重命名

- 完成行内新建文件夹和单项重命名。
- 覆盖名称验证、大小写改名、错误保留输入和多标签局部更新。

### P2.2 基础右键菜单外壳

- 完成空白处、单项、多选和键盘菜单入口。
- 先接入 AsterFiles 基础命令模型，确保所有入口共用命令路由。

### P2.3 剪贴板、复制与移动

- Windows 剪贴板互通。
- 单项到批量、文件到目录、同盘到跨盘、再到 UNC。
- 完成进度、取消、部分结果和失败项重试。

### P2.4 删除

- Windows 回收站删除与失败边界。
- 永久删除二次确认。
- 大目录快速移除和后台清理，验证崩溃后遗留记录可诊断。

### P2.5 冲突与完整任务中心

- 文件、目录和类型冲突。
- 覆盖、跳过、保留两者、对全部应用。
- 任务中心完整状态、速度、剩余项、取消、失败和重试。

### P2.6 系统经典菜单数据源

- 接入单文件、单目录、空白处，再扩展多选。
- 处理普通子菜单、图标、状态、调用和原生完整菜单出口。
- 基础文件命令去重并继续由 AsterFiles 接管。

### P2.7 收尾

- 多标签定向更新和批量事件合并。
- 快捷键、无障碍名称、中英文资源和高 DPI 检查。
- 完成真实磁盘、UNC、取消、冲突、退出和第三方菜单兼容性验收。

## 12. 验证计划

### 12.1 自动验证

- 单元测试：状态转换、事件顺序、冲突策略、名称生成、源目标关系、取消和重试集合。
- 集成测试：在临时目录验证新建、重命名、复制、同盘移动、跨盘模拟、目录合并、永久删除和部分失败。
- Windows 集成测试：剪贴板格式、回收站、长路径、Unicode、链接本身删除和菜单模型解析。
- Agent 场景：运行中、等待冲突、取消中、部分完成、失败重试和退出提示。
- 每个切片运行范围相符的测试，阶段完成运行 `python tools/verify.py` 与 `cargo build --release`。

### 12.2 人工矩阵

- 1 个大文件、1 万和 10 万个小文件、深层目录、空目录。
- NTFS 同盘、两个本地卷、移动硬盘和 UNC/SMB。
- 中文、日文、韩文、Emoji、组合字符、超长名称和仅大小写不同名称。
- Explorer → AsterFiles、AsterFiles → Explorer 的复制与剪切。
- NanaZip/7-Zip、Git、TortoiseSVN、PowerToys、发送到、属性、打开方式和管理员命令。
- 操作中导航、切换/关闭标签、关闭窗口、断开目标盘和撤销网络连接。

## 13. 完成标准

P2 完成需同时满足：

- 用户仅通过右键菜单和标准快捷键即可完成常见文件整理，不依赖 Explorer。
- 所有基础操作使用原始路径身份，UI 线程不访问磁盘或 COM。
- 跨盘和 UNC 操作可取消，部分成功、失败与重试结果准确。
- 回收站和永久删除边界明确，不发生静默永久删除。
- 大目录永久删除可快速从原位置移除，后台真实清理状态可见且可重试。
- 同一路径的所有标签最终一致，刷新只作用于受影响目录。
- 第三方菜单命令与文件任务状态相互独立，并始终有 Windows 原生完整菜单出口；扩展崩溃隔离属于 P3 验收。
- 关闭应用时会询问是否等待任务完成；用户选择取消后状态落定再退出。
- `python tools/verify.py` 和 `cargo build --release` 通过，Release 可执行文件已更新并报告时间与 SHA-256。
