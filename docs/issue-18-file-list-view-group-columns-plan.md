# Issue #18：Explorer 风格文件列表视图、分组与详情列方案

GitHub Issue：[完善 Explorer 风格文件列表视图、分组与详情列](https://github.com/LiuYangArt/AsterFiles/issues/18)

## 1. 背景与结论

AsterFiles 当前只有“详细信息、列表、网格”三种视图状态；网格尺寸固定，列表与网格语义尚未完整对齐 Windows File Explorer。详情视图固定显示名称、类型、大小、修改时间四列，只有列宽和顺序，没有列显隐、创建日期或列宽自适应。文件列表也没有用户可配置的“分组依据”。

本 Issue 对齐 Explorer 的核心查看与组织体验，但不复制整个 Windows 属性系统。范围固定为 8 个视图入口、6 种分组状态、5 个详情列，以及文件列表内的 `Ctrl + 滚轮` 连续视图切换。Authors、Tags、Title 和 Windows 全属性“更多…”不纳入本 Issue。

本方案同时覆盖普通目录与 Everything 搜索。搜索页继续保持独立布局与排序状态；首期不支持分组，因为稀疏分页无法在未加载完整结果时可靠确定跨页分组边界。

## 2. 已确认的产品范围

### 2.1 View 入口

对用户提供以下 8 个互斥入口：

1. 超大图标
2. 大图标
3. 中等图标
4. 小图标
5. 列表
6. 详细信息
7. 平铺
8. 内容

四档图标共用同一套二维虚拟化布局，仅使用不同的图标、卡片和间距预设。详细信息、列表、平铺、内容分别保留自己的信息层级和排版语义，不能只换名称或行高冒充不同视图。

内部按五类布局实现：详细信息、列表、图标、平铺、内容。8 个用户入口是稳定的视图预设；图标的四档尺寸不是四套独立渲染实现。

### 2.2 Ctrl + 滚轮

鼠标位于文件列表有效区域时，`Ctrl + 滚轮` 使用以下连续序列：

`内容 → 平铺 → 详细信息 → 列表 → 小图标 → 中等图标 → 大图标 → 超大图标`

- 向上滚动：向右移动一级，进入更大、更图形化的视图。
- 向下滚动：向左移动一级。
- 到达序列两端后保持不变，不循环。
- 标准鼠标滚轮每个刻度切换一级。
- 触控板像素滚动先按逻辑像素累计，达到一个明确阈值后切换一级；方向改变、松开 `Ctrl`、切换标签或导航后清空累计值。
- 单次事件最多切换一级，剩余增量保留，防止触控板一次滑动跳过多个视图。
- 仅在没有文本编辑、菜单、拖动、框选或重命名时生效。
- 鼠标位于标题栏、地址栏、侧栏、设置页、状态栏、菜单或弹窗时不响应。
- 处理成功后消费本次滚轮，不能同时滚动文件列表或缩放其他控件。

切换时以鼠标下的稳定 `EntryId` 作为首选锚点；鼠标下没有真实条目时使用首个可见条目。新视图尽量把锚点保持在原来的窗口内纵向位置。选择、焦点、锚点和重命名目标不得改变；切换不得重新枚举目录、创建新的导航 `RequestId` 或无条件回到顶部。

### 2.3 Sort by

现有名称、类型、大小、修改时间排序继续保留，并补充创建时间。排序字段和方向与分组字段和方向互相独立：

- 名称
- 修改时间
- 创建时间
- 类型
- 大小
- 升序 / 降序

详情表头点击仍调用同一排序命令。隐藏某一列不能取消或改变当前排序；当前排序字段不可见时，菜单仍必须明确显示勾选状态和方向。

### 2.4 Group by

普通目录首期提供：

- 无
- 名称
- 修改日期
- 创建日期
- 类型
- 大小
- 分组升序 / 分组降序

规则如下：

- “无”是默认值，恢复现有扁平布局。
- 分组只决定组的划分与组顺序；组内仍使用当前 Sort by 字段和方向。
- 目录与文件不得因为分组而丢失或重复；文件夹优先规则只在“无分组”或组内排序规则要求时生效，不能凌驾于组顺序。
- 名称分组、日期时间段和大小区间在实现前用当前 Windows 11 Explorer 建立人工对照夹具；实际边界和本地化文案按对照结果固化到纯函数测试，避免凭印象发明规则。
- 类型分组使用用户可见类型名称；内部比较仍使用稳定类型键，不能用本地化显示文案反向定位文件。
- 创建/修改日期按本地时区生成 Explorer 风格时间段；跨午夜、周/月/年边界刷新时只重算分组投影，不重新读取目录。
- 大小分组使用文件真实大小和已经取得的文件夹大小；未知文件夹大小先进入“未指定”组。需要补齐全部文件夹大小时复用现有有界后台调度，全部到达终态后一次提交跨组移动，避免列表持续跳动。
- 组标题显示本地化组名和项目数量，首期不可折叠、不可选择、不可重命名、不可作为拖放来源或文件操作目标。
- Everything 搜索页的 Group by 菜单首期禁用并给出本地化原因；不得对已加载单页进行伪分组。

### 2.5 详细信息列

列集合固定为：

- 名称：必须显示，不允许关闭。
- 修改时间：默认显示。
- 类型：默认显示。
- 大小：默认显示。
- 创建时间：默认隐藏。

详情表头的列菜单提供：

1. 调整当前列宽以适应内容；
2. 调整所有列宽以适应内容；
3. 名称、修改时间、类型、大小、创建时间的显示勾选。

现有拖动换序和拖动调宽继续有效。自动适应以当前已加载数据、表头和合理的最小/最大宽度计算，不为测量整目录而创建 UI 节点，也不读取未加载搜索页。名称列即使是唯一可见列也保留横向布局约束；隐藏列保留上次宽度和顺序，重新显示时恢复。

Authors、Tags、Title、访问时间、Git 列、云同步列、回收站列和 Windows 全属性“更多…”均不属于本 Issue。

## 3. 入口与菜单结构

本 Issue 不在顶部命令区、底部状态栏或其他现有区域增加按钮、分区或新的可见入口。功能入口严格限制为三处：

1. 文件列表空白处右键菜单：`查看`、`排序方式`、`分组依据`、`刷新` 位于 AsterFiles 内置命令区；Windows Shell 动态菜单继续位于其后。只有从文件列表空白区域打开时显示这些目录级命令，右键文件或文件夹仍显示条目操作菜单。
2. 详情表头右键菜单：仅提供当前列/全部列宽适应和列显隐，不承载 View、Sort by 或 Group by。
3. 文件列表内 `Ctrl + 滚轮`：直接调用相邻视图预设，不出现额外浮层或工具栏。

三个入口共用同一状态与命令；右键菜单打开时必须正确显示当前视图、排序、分组、列显隐和方向。菜单文案进入中英文资源，辅助功能名称不得使用裸符号代替。当前项勾选以及 `查看`、`排序方式`、`分组依据`、`刷新`、`新建文件夹`、详情列等 AsterFiles 自有命令使用内置图标；Windows 与第三方 Shell 菜单图标不属于本 Issue。

背景菜单属于 AsterFiles 内置命令，不依赖 Shell 扩展是否加载成功。它与 Issue #13 的快速菜单共享展示容器时仍保持独立命令身份；Shell 加载失败不得影响 View、Sort by、Group by 和 Refresh。现有底部三个视图按钮不属于本 Issue 的新增入口；本 Issue 不扩展或重排底部区域，是否另行移除应作为独立 UI 清理决策处理。

## 4. 状态模型与持久化

### 4.1 稳定状态

每个目录视图偏好包含：

- 8 选 1 的视图预设；
- 排序字段与方向；
- 分组字段与方向；
- 详情列的稳定列 ID、可见性、顺序和宽度。

偏好按 Rust 原始 `PathBuf` 键保存并在多标签、多窗口间共享；展示路径不能作为键。搜索结果使用独立的搜索视图偏好，包含视图、排序和列布局，不包含分组。

同一路径在两个标签中打开时，改变布局立即更新两个窗口的展示偏好，但不能改变各标签的选择、焦点、滚动锚点或导航请求。目录偏好持久化采用有界最近使用集合，避免会话文件随浏览路径无限增长；上限与淘汰规则在实现时作为明确常量和测试固定。

### 4.2 会话格式

当前正式格式使用固定四列数组，无法表达动态列和目录偏好。本 Issue 直接升级正式 ASTF 格式：

- 使用稳定枚举编号保存视图、排序、分组和列 ID；
- 保存原始路径编码，不保存本地化展示文本；
- 校验重复列、缺失名称列、非法宽度、未知枚举和超量目录记录；
- 旧格式直接拒绝，不增加兼容读取、迁移或回退。

### 4.3 临时状态

以下状态不持久化：

- `Ctrl + 滚轮` 像素累计值；
- 当前物理视口偏移；
- 视图切换前捕获的锚点与相对位置；
- 菜单展开状态；
- 分组投影缓存。

## 5. 数据与后台边界

### 5.1 创建时间

普通目录读取工作线程在已有元数据读取阶段同时取得创建时间，并随当前 `TabId + RequestId + EntryId + 原始路径` 数据提交；失败或不支持时为空值。不得为了显示列或分组在 UI 线程再次访问文件系统。

Everything 搜索结果需要把创建时间加入 Query2 请求字段，并增加对应服务端排序映射。返回值仍校验搜索 `RequestId + PageSource`。创建时间不可得时显示空值并使用稳定的未知值排序规则。

### 5.2 分组投影

领域条目仍保持扁平且只包含真实文件；组标题不得伪装成 `FileEntry`。协调层生成独立展示投影：

- 列表类视图：组标题行与真实条目行组成虚拟视觉行；
- 图标视图：组标题占整行，组内条目按当前列数生成二维虚拟行；
- 每个真实条目槽只保存稳定 `EntryId`，操作时回到当前标签的 Rust 原始条目解析；
- 视觉行维护固定高度和累计偏移，滚动、命中与锚点通过二分定位，不能继续假设所有行都是统一的 `项目数 × 行高`。

目录批次到达时只更新受影响组和累计几何；首批内容必须立即可见，不能等目录完整后才建立分组。异步图标、缩略图、选择和非分组字段回填只局部更新目标条目，不重建全部分组。

### 5.3 取消与迟到结果

新导航、刷新、关闭标签和退出继续取消旧目录、缩略图与文件夹大小工作。视图、排序、分组和列布局变化只改变当前条目投影，不生成导航请求。迟到的创建时间、文件夹大小、图标和缩略图仍按原有身份链路核对，不得写入新目录或错误组。

## 6. 五类布局语义

### 6.1 详细信息

- 有表头和可配置列；行内按统一列几何显示。
- 支持横向滚动、列换序、调宽与自适应。
- 图标使用紧凑尺寸，选中和命中仍以整行规则为准。

### 6.2 列表

- 仅显示图标与名称，按从上到下的紧凑单列虚拟列表展示。
- 不复用详情表头，不暴露隐藏列内容。
- 行高和图标尺寸独立于详细信息。

### 6.3 图标

- 小、中、大、超大图标共用真正的二维虚拟化卡片。
- 缩略图只请求当前可见区域及受控预取范围；视图尺寸变化重新计划可见请求，但不更换目录请求身份。
- 卡片名称允许受控换行；不同档位使用明确的最大行数与裁剪规则。

### 6.4 平铺

- 横向卡片：图标在左，名称和少量核心信息在右。
- 默认信息为类型和大小；文件夹大小未知时不显示伪 `0 B`。
- 采用固定卡片高度和多列二维虚拟化。

### 6.5 内容

- 宽行布局：较大图标、名称、类型、大小、修改时间组成可读摘要。
- 小窗口下按优先级隐藏次要信息，但不改变视图身份。
- 采用单列虚拟列表，不创建详情表头。

精确逻辑尺寸集中在一个布局几何表中，由真实 Windows 11 对照截图在 100%、125%、150% DPI 下校准；持久化只保存预设，不保存 DPI 换算后的像素值。大图标保持 `148px`，超大图标收敛为 `168px`；缩略图按活动视图尺寸与窗口 DPI 请求，缓存位图小于目标物理尺寸时重新提取，禁止放大低分辨率缓存。所有列表类和网格类视图左右各保留 `16px` 背景，条目点击、右键、框选与拖放不得吞掉这两个空白起点区域。

## 7. 统一几何与交互

新增布局必须统一覆盖：

- 窗口滚轮、触控板与自绘滚动条；
- 首尾、PageUp/PageDown、Home/End 和方向键；
- 单击、Ctrl/Shift 多选与 `Ctrl+A`；
- 框选与边缘自动滚动；
- 双击打开、重命名、右键命中；
- 应用内拖放、原生拖入和拖出；
- 可见范围文件夹大小、图标和缩略图调度；
- Everything 稀疏分页位置换算。

所有几何入口消费同一份活动布局描述和分组视觉行，禁止在滚轮、框选、拖放和滚动条中各写一套行高或列宽常量。隐藏布局拥有私有物理视口，不能回写当前活动视图；逻辑位置由稳定条目锚点跨布局转换。

## 10. 人工验收

项目规则禁止 Codex 操作 AsterFiles UI。用户需在真实窗口检查：

- 浅色、深色；普通目录与 Everything 搜索；
- 默认、窄窗口、最大化窗口；100%、125%、150% DPI；
- 空白处右键菜单的 8 个 View 选项、详情表头右键菜单和 `Ctrl + 滚轮` 连续顺序；
- 鼠标滚轮与真实触控板的单步、阈值和两端行为；
- 切换视图前后的可见文件、选择、焦点和滚动位置；
- 五类布局的信息层级、裁剪、缩略图清晰度和大目录滚动；
- 详情列显隐、换序、调宽、单列与全部列自适应；
- 普通目录的各分组字段、方向、增量加载与文件夹大小回填；
- 分组标题周围的点击、框选、右键、重命名和拖放边界；
- 多标签、多窗口和重启后的目录偏好恢复。

真实验收发现的精确尺寸和 Explorer 分桶差异应回写本方案及自动夹具，不以 Debug 手感替代证据。
