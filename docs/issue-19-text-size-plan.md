# Issue #19：设置外观文字大小方案

GitHub Issue：[在设置外观中增加全局文字大小](https://github.com/LiuYangArt/AsterFiles/issues/19)

## 1. 背景与结论

当前“设置 > 外观”只有主题选项，应用内文字大小分散在主窗口、设置页、自绘菜单、确认窗口和文件操作窗口中。直接放大现有文字会造成固定行高、卡片高度与鼠标命中区域不一致，因此本 Issue 同时统一字号入口和相关布局尺寸。

首版采用有限档位，不提供任意数值：

- 小：90%；
- 标准：100%，默认；
- 大：115%。

设置属于应用级外观状态，选择后立即作用于所有已打开的 AsterFiles 自绘窗口，新窗口继承当前值，退出后保存并在下次启动恢复。

## 2. 产品范围

### 2.1 包含

- 设置页新增“文字大小”独立卡片，位于“外观”的主题卡片之后；
- 主窗口的标签、导航、地址栏、侧栏、详情列表、紧凑列表、网格文字、状态页和状态栏；
- AsterFiles 自绘菜单、确认窗口和文件操作窗口；
- 简体中文、英文文案和可访问名称；
- 多窗口即时同步、跨重启保存。

### 2.2 不包含

- 图标、缩略图和窗口整体等比缩放；
- 文件列宽自动重置或按字号另存配置；
- Windows 原生经典菜单和其他系统窗口；
- 单独设置文件列表字号；
- 任意百分比、输入框、连续滑块或跟随 Windows 文本大小设置。

## 3. 交互与展示

“文字大小”使用与主题一致的三档单选卡片：小、标准、大。当前档位使用现有强调色和边框表达，必须提供可访问名称及当前选中状态。

用户选择后立即更新当前进程内所有窗口，不要求重启，也不重新加载目录、搜索、图标或缩略图。设置页自身同步变化，因此卡片、标题和选项不能因切换到“大”而截断。

## 4. 样式设计

在 Slint 的统一视觉入口中建立语义字号，而不是继续让页面直接使用散落的像素值。至少区分：

- 辅助文字；
- 正文；
- 强调正文；
- 小标题；
- 页面标题；
- 窗口标题。

各档位由同一倍率派生，最终逻辑像素采用确定的取整规则，避免同一层级在不同页面得到不同结果。现有直接写死的字号逐步替换为这些语义入口；图标字符如果承担图标作用，不随正文字号入口变化。

字号增大时，承载文字的行高、内边距和固定窗口高度必须同步采用明确的布局尺寸。详情、紧凑和网格视图的视觉行距与 Rust 侧滚动、选择、框选、命中和可见范围计算必须继续使用同一份几何常量，禁止只改 Slint 高度。

## 5. 状态与持久化

定义三个稳定档位：Small、Standard、Large，默认 Standard。应用状态是唯一真实来源；Slint 只显示当前档位并提交选择意图。

数据流：

1. 启动时从会话读取档位并传入应用状态；
2. UI 选择后由协调层更新应用状态；
3. 刷新所有已注册主窗口，以及操作窗口和确认窗口；
4. 新建窗口直接读取当前应用状态；
5. 正常退出时保存档位。

会话格式从 `ASTF8` 直接升级为新正式版本。按项目规则不读取、不迁移旧格式，也不增加回退；无效档位应拒绝加载。会话编码/解码、构造入口、样例和损坏数据测试必须同步更新。

## 6. 架构边界

- 文字大小是应用级设置，不属于标签、窗口或路径状态；
- 改变档位不生成新的 `TabId`、`RequestId` 或目录/搜索任务；
- 不在 UI 线程读取磁盘、Shell、COM、网络或系统设置；
- 不改变文件原始路径、稳定条目身份、列顺序和列宽；
- 多窗口共享同一档位，不提供每窗口覆盖；
- 独立窗口必须接收同一外观状态，不能各自保存副本；
- 用户可见新增文案进入现有中英文资源入口。

## 7. 实施切片

1. 新增文字大小档位、默认值、校验和会话格式升级，补齐持久化测试。
2. 在统一视觉入口建立语义字号和对应布局尺寸，保持标准档与当前视觉一致。
3. 将主窗口、设置页、自绘菜单和状态页迁移到语义字号。
4. 将确认窗口、文件操作窗口及新建窗口接入应用级即时同步。
5. 增加外观设置卡片、中英文文案、回调和可访问状态。
6. 对齐详情、紧凑、网格的 Slint 与 Rust 几何计算，补齐自动测试。
7. 更新本方案、任务清单与 `foundation-plan.md` 状态，自动验证后交给用户人工验收。

## 8. 自动验证

至少覆盖：

- 三个档位映射、默认值、非法值拒绝；
- 会话写入和重启恢复；
- 设置变化不会改变标签、请求身份、路径、列顺序或列宽；
- 所有已打开窗口同步，新窗口继承；
- 标准档保持现有字号和几何；
- 详情、紧凑、网格的行高、滚动位置、点击、选择、框选和可见范围换算一致；
- 简体中文与英文新增文案完整；
- 大字号下关键固定窗口的布局约束不溢出。

完成实现后运行：

```powershell
python tools/verify.py
cargo build
```

机器可读汇总保留在 `artifacts/verify/summary.json`。交付时报告 `target/debug/asterfiles.exe` 的修改时间与 SHA-256。用户确认 Issue 完成前不构建 Release。

## 9. 人工验收

项目规则禁止 Codex 操作 AsterFiles UI。用户需在真实窗口检查：

- 小、标准、大三档立即生效且重启保持；
- 已打开的多个主窗口、确认窗口和文件操作窗口同步；
- 浅色与深色、简体中文与英文；
- 默认、窄窗口、最大化窗口；
- Windows 100%、125%、150% DPI；
- 详情、紧凑、网格、设置、菜单、错误页和状态栏无裁切、重叠或错误换行；
- 列表滚动、点击、双击、选择、框选、重命名和拖放命中仍准确；
- Windows 原生菜单和图标尺寸保持原样。
