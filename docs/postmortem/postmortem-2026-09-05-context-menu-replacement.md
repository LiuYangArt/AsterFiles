# #52 重复右键菜单的输入生命周期

## 症状与证据边界

用户反复报告：菜单打开后，对另一个文件夹右键只关闭旧菜单。
此前试验已全部回退。本次检查发现主窗口两处 `Focused(true)` 直接隐藏
菜单，而文件项必须收到完整的按下和释放才会打开对象菜单。
单纯命中测试和菜单几何测试无法证明 Windows 实际分发了这两个事件。
焦点期间隐藏弹窗是代码中明确存在的时序风险；真实输入根因仍需人工日志验证。

## 修正后的边界

- 主窗口重新激活不隐藏菜单，也不在这时刷新快速访问并重新投影主界面。
- 鼠标释放先交由 Slint 实际命中的控件处理，不按全局鼠标状态猜测目标。
- 释放后的清理仅对原根分支身份生效：控件已打开新根分支则保留新菜单；
  未替换则关闭旧菜单，包括左键及不支持菜单的区域。
- 新文件内容区菜单先结束旧 Shell 会话，再投影缓存并申请新请求。
- 不修改 Windows 激活消息、鼠标捕获或窗口隐藏实现。

## 验证与后续入口

新增回归覆盖同一 Shell 代次内根分支替换、旧清理失效以及旧子菜单移除。
已有命中测试覆盖对象与空白切换、滚动偏移；完整非 UI 验证输出在
`artifacts/verify/summary.json` 和 `artifacts/logs/`。

项目禁止自动操作真实 UI。人工需验证列表和网格的空白→文件夹、A→B、
文件夹→空白、带子菜单替换、多选成员右键、左键外部关闭。
构建和纯状态测试不能替代这些验收，也不能证明首次原生右键没有被吞掉。
若仍失败，下一步以 `wire_mouse_navigation` 的窗口事件与
`wire_internal_drag_drop` 的按下/释放入口日志定位，不叠加全局按键探测。
