# #52 重复右键菜单的输入生命周期

## 结论

最终修复是把内容区空白菜单从右键按下触发改为右键释放触发，使它与文件项、侧栏菜单使用相同的输入边界。按下阶段创建独立 popup 会提前改变窗口和鼠标路由，导致后续 folder 没有 hover、光标不变，第二次右键仍被识别为空白区域。

## 症状与证据边界

用户反复报告：菜单打开后，对另一个文件夹右键只关闭旧菜单；空白菜单尤其容易复现，文件夹和侧栏菜单则可以正常切换。
此前试验已全部回退。本次检查发现主窗口两处 `Focused(true)` 直接隐藏
菜单，而文件项必须收到完整的按下和释放才会打开对象菜单。
单纯命中测试和菜单几何测试无法证明 Windows 实际分发了这两个事件。
焦点期间隐藏弹窗是代码中明确存在的时序风险，但它不是最终根因。最终根因是空白菜单在 `PointerEventKind::down` 阶段打开，先于文件项的完整按下/释放序列创建 popup。

## 修正后的边界

- 主窗口重新激活不隐藏菜单，也不在这时刷新快速访问并重新投影主界面。
- 内容区空白菜单在 `PointerEventKind::up` 阶段打开；文件项和侧栏菜单同样在释放阶段处理右键。
- 鼠标事件先由 Slint 实际命中的控件处理，不按全局鼠标状态猜测目标。
- 释放后的清理仅对原根分支身份生效：控件已打开新根分支则保留新菜单；
  未替换则关闭旧菜单，包括左键及不支持菜单的区域。
- 新文件内容区菜单先结束旧 Shell 会话，再投影缓存并申请新请求。
- 不修改 Windows 激活消息、鼠标捕获或窗口隐藏实现。

## 验证与后续入口

新增回归覆盖同一 Shell 代次内根分支替换、旧清理失效以及旧子菜单移除；编译验证覆盖空白菜单触发时序改动。
已有命中测试覆盖对象与空白切换、滚动偏移；完整非 UI 验证输出在
`artifacts/verify/summary.json` 和 `artifacts/logs/`。

项目禁止自动操作真实 UI。人工需验证列表和网格的空白→文件夹、A→B、
文件夹→空白、带子菜单替换、多选成员右键、左键外部关闭。
构建和纯状态测试不能替代这些验收，也不能证明首次原生右键没有被吞掉。
若类似问题再次出现，先对照各右键入口的 down/up 触发边界，再检查 popup 创建是否发生在实际命中控件完成释放之前；随后用 `wire_mouse_navigation` 与 `wire_internal_drag_drop` 的按下/释放入口日志定位，不叠加全局坐标猜测或额外焦点旁路。
