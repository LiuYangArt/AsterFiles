# Issue #45 大目录缩略图快速滚动崩溃复盘

日期：2026-09-04

影响范围：文件较多的本地目录、缩略图模式、快速大跨度拖动滚动条

状态：已修复；用户已在 `D:\Downloads` 的真实窗口中确认不再崩溃

## 摘要

在文件较多的目录中，缩略图模式快速拖动滚动条会让 Debug 和 Release 进程直接退出。根因是界面按缩略图网格的实际行高滚动，而文件夹大小调度仍按固定的详情行高换算首行；大跨度跳转会得到超过条目总数的起点，随后对列表执行无效范围切片并触发 Rust panic。

修复在形成切片前把起点限制到条目总数，并补充“可见范围已越过末项”的回归测试。用户使用更新后的 Debug 版本复测通过。

## 用户可见症状

- 在 `D:\Downloads` 等文件较多的目录切换到缩略图模式。
- 快速、大跨度拖动滚动条时窗口直接退出。
- Debug 和 Release 均可复现。
- 当次复现没有生成新的 Windows 错误报告或崩溃转储。

## 根因

缩略图网格的行高会随尺寸档位变化，而滚动后的文件夹大小请求仍使用详情视图的固定行高估算首行。快速把滑块拖到较深位置时，估算出的首行可能远大于当前目录条目总数。

调度器原先只限制了范围终点，没有限制起点。起点超过列表长度后，形成的范围会变成“起点大于终点”，Rust 的切片边界检查随即 panic。该错误与缩略图解码、缓存容量和 Windows Shell 无关，因此继续围绕转储排查不会命中根因。

## 为什么当时没有新转储

Windows 错误报告和 `CrashDumps` 更适合记录原生访问冲突。此次退出来自 Rust 的确定性边界 panic，Debug 和 Release 都可能直接终止而不留下同类转储。因此，排查不能只依赖 WER；还必须审查从滚动位置到可见范围的所有边界，并用极端位置做无界面测试。

## 修复

- 可见范围起点在切片前限制到条目总数。
- 保留饱和加减，避免极端滚动数值发生整数溢出。
- 增加越过末项的回归测试，确认返回空请求而不是崩溃。
- 未改动缩略图架构、缓存和正常滚动行为。

## 防复发规则

1. 任何由滚动位置换算出的列表范围，起点和终点都必须在访问前限制到当前模型长度。
2. 可见范围允许落在模型末尾之外；合法结果是空集合，不得把它视为调用方一定会避免的状态。
3. 网格与详情视图使用不同几何时，不得假设固定行高能准确表示另一种视图的位置。
4. 快速拖动、窗口缩放和模型替换可能让几何与模型短暂不同步；调度边界必须自行安全处理。
5. 崩溃没有新 WER 或转储时，应同时检查 Rust panic、断言和切片边界，不要据此排除真实退出。
6. 回归测试必须包含远超末项的首行，而不只覆盖首尾相邻的正常范围。
