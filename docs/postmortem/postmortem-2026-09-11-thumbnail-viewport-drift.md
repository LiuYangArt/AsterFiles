# Issue #88 大图片目录缩略图停止与视口错位复盘

日期：2026-09-11

影响范围：包含大量图片的本地目录、网格视图、连续滚动和滚动条大跨度跳转

状态：已修复；用户已完成真实窗口验收

## 摘要

在 2743 张图片的 Screenshots 目录中，缩略图会留下少量占位，继续滚动后停止加载；修正调度竞态后，又暴露出加载区域随滚动深度逐渐偏离实际可见行。问题并非单一缓存容量不足，而是三处边界叠加：旧队列不能及时让位给当前视口、重复视口更新误丢仍可见的在途结果、Rust 与 Slint 使用了不同的行高。

最终修复把缩略图工作改为有界、可替换的当前视口计划；结果以稳定项目身份直接更新；失败项有限重试；并统一所有文件视图的几何尺寸。用户使用真实目录连续滚动后确认行为符合预期。

## 用户可见症状

- 首次打开或向下滚动时，当前屏固定留下约两个未加载占位，回滚后才可能补上。
- 滚动到一定位置后，下方缩略图不再加载。
- 第二轮修复后，缩略图仍会加载，但加载位置逐渐落后于实际可见行。
- 失败回退曾把低清文件图标放大，视觉模糊。

## 根因

### 1. 旧任务阻塞当前视口

缩略图使用无界先进先出队列。同一目录快速滚动时，已离开预取范围的待处理项仍占据队列，当前可见项只能排在后面。

### 2. 视口代次判断过严

每次滚动回调都会更新计划。原实现要求结果同时匹配创建任务时的代次；两个正在提取、且仍在当前视口中的项目，会因一次重复回调变成“旧代次”并被丢弃。持续滚动会把这些小缺口累积成大片占位。

有效性真正依赖的是稳定项目是否仍属于当前计划，而不是计划编号是否完全相同。代次仍用于替换未开始工作，但在途结果按当前成员关系验收。

### 3. 渲染与调度的行高不同

可见范围由真实滚动位置配合 Rust 行高换算。Slint 大图标实际使用 180px，Rust 曾使用 196px；每行产生 16px 累积误差。滚动越深，调度范围与实际可见行偏差越大。详情、列表和其他图标尺寸也存在类似差异，相关滚动、搜索、命中和框选计算都受影响。

### 4. 失败回退污染缓存

缩略图提取失败后，大尺寸文件图标被当作结果缓存，既阻止后续缩略图重试，又在大图标视图中被放大。

## 修复

- 每个标签维护最多 96 项的当前视口计划；新视口替换未开始的旧工作，并优先最近更新的标签。
- 仍处于当前视口或预取范围的在途结果可以完成；真正离开范围的结果被拒绝。
- 使用 `EntryId` 到网格槽位的索引直接更新结果，避免每张图片扫描全目录。
- UI 行模型只保留当前可见和预取范围的缩略图像素；离开范围后释放，缓存仍保持 128 项上限。
- 等待状态使用固定尺寸矢量占位；失败不再缓存放大的低清图标，两秒后仅自动重试一次。
- Rust 的详情、列表、小/中/大/超大图标、平铺和内容视图尺寸与 Slint 当前布局完全对齐；滚动、搜索定位、点击命中、框选和文件夹大小范围同步更新。

## 防复发规则

1. 可见范围只能由真实视口坐标和与渲染完全一致的几何计算；同一尺寸不得在 Rust 与 Slint 中独立演化。
2. 取消未开始工作与接收在途结果是两条规则：计划更新不能仅凭代次丢弃仍属于当前视口的结果。
3. 大目录后台队列必须有界、可替换并优先当前视口；缓存上限不能替代队列背压。
4. 缩略图失败状态不得伪装成成功缓存；占位、成功和最终失败必须保持独立。
5. 自动化必须覆盖深滚动累积误差和重复视口回调，不能只验证首屏与单次跳转。
6. 大目录修复必须经过真实窗口连续滚动验收；纯调度测试不能证明坐标与渲染一致。
