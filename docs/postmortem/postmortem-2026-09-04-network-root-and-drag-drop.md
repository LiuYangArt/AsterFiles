# Issue #10 网络根目录崩溃与滚动路由复盘

日期：2026-09-04

影响范围：Windows 网络设备根、UNC 路径、原生拖放退出顺序、侧栏与文件列表滚动

状态：用户已确认点击 `LiuYanghomeNAS`、访问 `\\LiuYanghomeNAS\` 和侧栏滚动不再崩溃或串区

## 摘要

本轮存在两个先后出现、表象相同的崩溃。第一类发生在进程退出阶段：拖放注册对象直到线程本地存储销毁时才调用 Windows 注销接口，此时 COM/OLE 已在卸载，最终于 `combase.dll` 访问冲突。第二类发生在网络根结果投影阶段：Windows Rust 路径规则把 UNC 的服务器与共享视为路径前缀，`file_name()` 对 `\\server\share` 返回空，而调试断言把共享误当作普通末级目录名，导致 Debug 进程退出。

同时，窗口级滚轮路由只判断了纵向范围，鼠标位于侧栏时仍可能滚动右侧文件列表；侧栏状态栏也错误参与左侧内容高度。最终分别修正了拖放生命周期、UNC 组件解析与二维命中范围，并把状态栏固定在右侧列表下方。

## 用户可见症状

- “网络”最初发现慢且每次展开都会重新寻找设备。
- 点击设备名或在地址栏提交 `\\LiuYanghomeNAS\` 后，窗口直接退出。
- 已保存的网络位置先进入包含 `target.lnk` 的 Explorer 快捷目录，而非直接进入目标共享。
- 从 NAS 拖文件到本地后，NAS 文件列表回到顶部。
- 矮窗口中侧栏没有滚动条，滚轮位于侧栏时反而滚动文件列表；右侧状态栏可能被挤出窗口。

## 根因

### 1. Windows 拖放注销发生得太晚

崩溃转储的稳定调用链为 `LdrShutdownProcess → ThreadApartment TLS destructor → DragDropRegistration::drop → RevokeDragDrop → combase.dll`。拖放注册依赖窗口句柄和 OLE apartment，却把关键注销交给线程本地对象的析构顺序。进程卸载阶段再进入 `RevokeDragDrop` 已不安全。

修复后，事件循环返回时先撤销全部窗口拖放注册，随后保存窗口与会话状态、清空窗口运行时，最后释放 OLE apartment。TLS 析构不再承担 Windows API 注销工作。临时的 `mem::forget` 规避被删除，避免用泄漏掩盖生命周期错误。

### 2. UNC 共享不是普通路径末级组件

`\\LiuYanghomeNAS\Container` 在 Windows 路径语义中包含 UNC 前缀与共享名，不保证 `Path::file_name()` 返回 `Container`。网络根枚举本身已经成功，但把共享转换成文件行时触发了只适用于本地目录的调试断言。

修复后，网络根条目从原始 UTF-16 UNC 身份中提取服务器后的共享组件，不经有损字符串转换，也不再用本地路径末级规则验证 UNC 根条目。真实 NAS 测试曾在这里稳定失败，修改后成功返回 8 个共享。

### 3. 滚轮命中只使用纵坐标

窗口事件层只判断指针是否低于文件列表顶部，忽略右侧内容区的左边界，因此侧栏滚轮也被当成文件列表滚轮。侧栏自身虽可溢出，但没有成为明确的滚动接收区。

修复后，窗口级文件列表滚轮使用完整二维矩形命中；侧栏使用独立滚动视口并消费自身滚轮。右侧状态栏从左侧布局高度中解耦，始终固定在文件列表下方。

### 4. 设备发现缓存更新时机错误

刷新开始时曾立即清空上次设备列表。刷新失败、取消或应用退出会把空结果持久化，下一次启动仍需重新发现。修复后仅在一次发现成功完成时替换快照；失败与取消保留最近一次成功结果。

## 为什么排查时间较长

- 网络辅助进程与主程序使用同一个可执行文件名，WER 初看无法区分崩溃主体。
- “点击 NAS 后退出”把触发动作与实际退出阶段混在一起；没有符号时 `combase.dll` 不能直接指出拖放注销。
- 修复原生退出崩溃后又出现 UNC 调试断言，两个问题的用户表象完全相同。
- 早期测试只覆盖网络枚举是否成功，没有覆盖“枚举结果 → 领域条目 → UI 文件行”的完整投影链。
- 滚轮测试只验证了内容溢出，没有验证指针位于左右两个区域时的路由边界。

## 未奏效或不完整的路径

- 只把网络枚举移到辅助进程：解决阻塞与隔离，但无法修复主进程退出时的拖放生命周期。
- 将拖放注册对象遗忘到进程结束：短期避开析构调用，却泄漏 COM 对象，且没有建立正确关闭顺序。
- 用 `Path::file_name()` 统一处理本地和 UNC：代码看似一致，但违反 Windows UNC 前缀语义。
- 只看网络请求完成日志：能证明枚举完成，不能证明后续投影和 UI 刷新没有 panic。
- 只给侧栏加滚动条：若窗口级滚轮仍错误接管，用户依旧无法滚动侧栏。

## 防复发规则

1. UNC 身份必须按 Windows UNC 组件解析；不得假设本地路径的末级名称、父级和根规则同样成立。
2. 网络测试必须覆盖枚举、领域模型、展示投影和操作提交的端到端边界，不能停在系统调用成功。
3. COM/OLE 注册必须由显式生命周期拥有；所有 Windows 注销调用在窗口有效且 apartment 未释放时完成。
4. 线程本地析构只释放纯 Rust 状态，不执行依赖进程、窗口或 COM 初始化顺序的系统调用。
5. 崩溃排查同时核对 PID、请求阶段日志、WER 和转储调用栈，区分主程序、辅助进程、Rust panic 与原生异常。
6. 缓存只在成功完成时替换；开始刷新、失败和取消不得破坏最近一次成功结果。
7. 分栏界面的滚轮接管必须使用二维命中范围；布局测试同时覆盖左右区域、矮窗口和内容溢出。
8. 自动测试不能代替真实 Windows Shell、Explorer、NAS 和 DPI 交互验收。
