# 文件列表列几何、调宽与排序回归复盘

日期：2026-08-30
影响范围：普通目录与 Everything 搜索结果的详情列表、列标题、横向滚动、列宽持久化和排序
状态：已修复；用户已确认列对齐、调宽、换序和排序交互可用

## 摘要

Issue #1 的修复曾多次在编译和静态检查通过后被误判为接近完成，但真实窗口中仍存在表头与内容错位、分隔符不可拖动、标题点击或换序失效，以及文件夹大小排序不符合预期。

核心教训是：详情列表的“统一列几何”不仅是共享列宽。表头与内容还必须共享可视容器、内容原点、横向滚动状态、列顺序和每列内容内边距；名称列的图标槽也必须是列描述的一部分。虚拟列表自身的水平视口若与自定义横向滚动并存，会形成第二套隐式位移，即使代码中的列宽完全相同，最终像素仍会错位。

## 用户可见症状

- 名称标题落在图标和名称文字之间，类型与修改时间内容整体比标题向右偏约 20 多像素。
- 大小标题按资源管理器规则左对齐，但数值右边界过度靠近下一列。
- 窄窗口或横向滚动后错位更加明显。
- 类型排序最初只区分“文件夹/文件”，后来虽然显示扩展名，文件夹仍被固定置顶，没有真正参与类型顺序。
- 文件夹大小异步返回后列表未重新排序；降序时未知大小还会被反转到有大小文件夹之前。
- 分隔符、排序和换序的手势区域互相覆盖，静态阅读无法证明真实鼠标链路可用。

## 根因

### 1. 共享列宽不等于共享最终几何

表头从 16px 可视原点开始，内容行则嵌套在选择背景和行容器中。多层 `x` 偏移虽然局部看似能相加到同一数值，但 `ListView` 还维护自己的水平视口，最终内容坐标受到隐式位移影响。自定义 `file-viewport-x` 再移动一次后，表头和内容不再处于同一坐标系。

### 2. 列描述遗漏内容语义

早期实现只有列宽和通用 padding，名称标题另外加图标补偿。这样表头和行消费的并不是同一份几何。名称列需要明确的 `content-left`、`content-right` 与 `icon-slot`；其他列也必须从相同描述读取内容边距。

### 3. 大小列混淆文字方向与边界一致性

Windows 文件资源管理器中，“大小”标题左对齐，数值右对齐。二者无需共享文字起点，但数值必须使用列描述中的统一右边距。把标题也改成右对齐并不能解决边界问题。

### 4. 排序比较器把多个规则错误地绑在一起

全局“文件夹优先”被无条件用于所有排序字段，导致类型排序中目录永远置顶。大小排序使用 `Option` 或状态元组直接反转，降序时未知大小随整体比较结果一起翻到最前。

### 5. 异步文件夹大小没有触发当前排序重算

目录先以未知大小显示，Everything 随后异步返回真实大小。仅更新单行显示不会改变已有列表顺序；当前排序字段为大小时必须在每次有效更新后重新排序并重建项目索引。

### 6. 鼠标命中区和状态刷新边界不清

表头主体覆盖整列，调宽区域又跨出列边界，容易被相邻列裁剪或抢走。调宽过程中如果只改 Slint 本地状态，而 Rust 的普通刷新重新写回旧宽度，视觉上会像完全拖不动。换序释放后若继续触发 `clicked`，还会意外排序。

### 7. 无效 UI 自动操作制造了伪证据

曾重复使用错误的屏幕坐标模拟拖动。截图没有光标、轨迹、事件计数或宽度前后状态，且持久化宽度没有变化，不能证明交互成功。发现证据无效后仍继续采用同一方法，延误了真正的代码排查。

## 修复

- 普通目录和搜索模式分别保存按稳定列 kind 索引的列宽，正式会话格式升级为 ASTF6，不提供旧格式迁移。
- 表头和内容共享列顺序、根级宽度、可视容器宽度、16px 内容原点与唯一 `file-viewport-x`。
- 固定虚拟列表的水平视口宽度，禁止其产生第二套隐式横向偏移。
- 列描述使用 `content-left`、`content-right`、`icon-slot`；名称标题与名称文字同起点，图标作为名称单元格内前缀。
- 类型、修改时间标题与内容共享左边距；大小标题保持左对齐，数值按共享右边距右对齐。
- 排序/换序主体与 16px 调宽命中区物理分离；拖动基于按下时宽度和绝对指针差，并在移动期间同步 Rust 状态；普通刷新不覆盖拖动态。
- 类型列显示扩展名文件类型；按类型排序时文件夹作为 `Folder` 类型参与整体顺序，不套用文件夹优先。
- 其他排序继续文件夹优先；大小排序在文件夹组内使用已索引真实大小，未知/未索引状态在升降序中都稳定放在已知大小之后。
- 有效文件夹大小事件在当前按大小排序时立即重新排序并重建索引。

## 防复发规则

1. “统一列几何”必须包含列顺序、宽度、可视容器、内容原点、横向滚动、左右内边距和名称图标槽；只共享宽度不算完成。
2. 表头与虚拟列表必须处于同一水平坐标系。使用自定义横向滚动时，必须显式禁用或固定控件自身的水平视口。
3. 选择背景的圆角边距不得承担列坐标；视觉背景与列内容原点应分开定义。
4. 大小列遵循 Explorer：标题左对齐、数值右对齐、数值右边距一致。
5. 排序规则按字段独立定义。不得无条件把“文件夹优先”套在类型排序；未知值的稳定位置不得随升降序反转。
6. 异步补充任何当前排序键后，必须重新排序并重建稳定身份到可见位置的索引。
7. 调宽、换序和排序命中区必须互斥；拖动释放不得继续触发点击排序。
8. 调宽过程不得触发会重建大目录模型的全量刷新，也不得被普通刷新写回旧状态。
9. UI 证据必须同时包含操作目标、前后状态和可读取结果。坐标错误、状态未变化或无法证明事件链路的截图立即作废，不得重复当作验证方案。
10. 用户明确要求人工验证时，停止 UI 自动操作，只交付可测试构建、验证步骤和状态证据。
