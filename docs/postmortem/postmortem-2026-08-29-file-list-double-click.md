# 文件列表排序表头与双击打开回归复盘

日期：2026-08-29
影响范围：文件列表命令区、列标题、鼠标双击、导航后的增量列表、鼠标侧键后退
状态：已修复

## 摘要

文件列表曾同时存在两类问题：排序入口与列标题重复且列标题未和内容严格对齐；双击打开在首次选中、导航后返回、窗口重新激活以及鼠标侧键后退后不稳定，用户有时需要点击三次。

问题不是单一的“焦点丢失”，而是多个输入和数据状态边界叠加：选择更新会改变行状态；增量加载期间界面显示新批次，但打开查询仍可能使用旧列表；Slint 内部双击回调依赖同一控件完成完整点击序列；鼠标侧键回调又在原生事件分发期间同步导航并替换列表模型。

## 用户可见症状

- “全选/清除选择”和四个独立排序按钮占据额外一行，与可点击列标题重复。
- 排序标题虽设置了左对齐，但文字控件没有占满列宽，视觉上仍像居中。
- 未选中项目直接双击、进入目录后返回再双击、窗口从非活动状态恢复后双击，偶尔需要第三次点击。
- 通过鼠标侧键后退时最容易稳定复现三击问题。

## 根因

### 1. 表头布局约束不完整

只设置文字的左对齐属性不足以保证列内左对齐。除名称列外，文字控件仍按内容宽度参与布局，没有占满所属列，因此左对齐没有可见效果。

### 2. 打开逻辑依赖易失的控件双击状态

Slint 的 `double-clicked` 要求同一个 `TouchArea` 完成两次完整的按下/释放序列。首次点击触发选择、模型行更新、窗口激活或导航后的控件重建时，框架可能取消当前序列，应用层收不到预期双击。

### 3. 增量加载的显示数据与点击数据不一致

`Partial` 状态显示 `pending_entries`，原打开路径却查询已提交的 `entries`。项目编号会在每次目录读取中复用，因此返回目录后可能查不到当前可见项目，甚至解析到旧目录的同编号项目。

### 4. 鼠标侧键在原生事件分发中同步导航

侧键释放事件直接调用后退并刷新整个界面，导致列表模型在鼠标事件仍在分发时被替换。紧随其后的第一次左键序列可能无法形成 Slint 的完整 `clicked`，表现为需要第三次点击。

## 修复

- 删除独立的全选、清除选择和排序按钮，保留键盘与多选能力。
- 排序入口合并到名称、类型、大小、修改时间表头，点击切换方向。
- 表头和数据行使用同一组列宽；文字控件显式占满所属列，名称标题补偿图标宽度和间距。
- 文件行改由应用层按 Windows 系统双击时间识别连续点击，不依赖 Slint 内部双击计数。
- 双击候选包含标签、加载批次和项目身份，避免跨目录或跨标签误判。
- 打开操作统一查询当前可见数据；增量加载期间使用 `pending_entries`，完成后使用 `entries`。
- 鼠标侧键的按下和释放都被拦截；释放时仅投递下一轮事件循环执行的导航，避免在原生事件分发期间重建列表。

## 防复发规则

1. 列标题和数据行必须复用同一列顺序、宽度、可见条件和间距；仅设置文字对齐不算完成。
2. 任何“当前可见项目”的选择、打开、重命名和菜单操作必须查询同一个可见数据源。
3. 双击状态必须绑定页面代次和稳定项目身份，不得只保存可跨目录复用的行号。
4. 原生鼠标事件过滤器不得同步执行会替换主要 UI 模型的导航；应投递到下一轮事件循环。
5. 列表交互至少覆盖：未选中/已选中项目、窗口重新激活、工具栏后退、鼠标侧键后退、加载首批数据时双击。
6. 真实桌面鼠标验证不可由编译或领域测试替代；无法自动化时必须明确列为人工验收项。
