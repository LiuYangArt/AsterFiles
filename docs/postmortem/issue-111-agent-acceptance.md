# #111 Agent 操作验收与工具权限排查复盘

日期：2026-09-14
关联：[AsterFiles #111](https://github.com/LiuYangArt/AsterFiles/issues/111)

## 发生了什么

#111 要让 Agent 通过稳定的应用层入口理解并执行常用操作，并改善菜单、按钮、文件条目的无障碍信息。初次回复把真实窗口验证交给用户，后续又因取消时机和工具权限问题多次留下未验证项，增加了用户的沟通负担。真实窗口验收随后发现 Shell 菜单命令标识重复，以及取消操作后冲突窗口残留两个实际问题。

本文记录排查经验与证据边界，不维护第二份任务清单。完整 Debug 验证通过（676 项通过、7 项跳过）；修复后的真实冲突取消复测确认任务结束、冲突窗消失且目标内容未变。最终范围和状态以 GitHub Issue 为准。

## 授权判断应使用完整会话

项目长期 AGENTS 规则禁止 Agent 操作 AsterFiles UI，但用户本次明确授权“本次可以由 Agent 操作 AsterFiles 做验收”。这项单次授权优先于项目文件中的一般约束，也不意味着永久删除长期规则。

验收开始前应核对本次授权、应用入口与可用工具。获得授权且工具可用后，应由 Agent 完成操作和证据采集，不能反复要求用户承担本可自动完成的验收。窗口可访问只证明工具连接成功，不能替代具体业务操作的结果。

## 取消验证必须有可重复的等待状态

最初使用两份各 8 GiB 的文件尝试复制后立即取消，复制在点击取消前已完成。这只能证明测试没有命中取消窗口，不能证明取消成功，也不能证明取消功能失效。继续扩大文件只增加磁盘占用，仍不能保证时机。

后续改用同名、几字节的测试文件制造冲突，使真实复制任务停在等待冲突处理的状态，再通过操作任务的取消入口发起取消。冲突弹窗里的“跳过”是跳过某个项目，不能冒充取消整个任务。证据应同时确认任务终态、源和目标内容，以及相关弹窗是否收起。

真实取消暴露出任务取消后冲突窗口仍残留。新增收尾判断读取冲突窗口绑定的操作 ID，仅在对应任务已离开等待冲突状态、取消标记已设置或任务已移除时清空并隐藏窗口。不能因为另一个任务结束就关闭当前仍待处理的冲突窗口。相关测试覆盖无关任务、目标取消、终态、任务消失与空 ID；重新构建后的真实窗口复测确认冲突窗消失，证据见 cancel-fixed-before.txt 与 cancel-fixed-after.txt。

## 菜单标识必须代表实际命令

Shell 菜单的多个叶子命令曾共用 `node=0`，Agent 无法依赖标识稳定区分动作。修复使用菜单会话与实际命令 ID 区分叶子项，子菜单仍使用节点身份。重新构建后的真实窗口中已确认不同命令具有不同标识。

单看显示名称不足以证明操作身份正确。窗口、标签、目录请求、文件条目和菜单会话都具有生命周期；后续排查应检查实际身份，不把翻译后的名称反向当作操作目标。

## 区分应用缺陷、工具缺陷与证据缺口

本次 Computer Use 返回的文本树没有完整呈现 selected、checked、expanded 状态值。Slint 控件测试可以验证声明和绑定，但不能据此声称 Windows 实际无障碍树也暴露了同样的值。报告应分别标明控件测试结果、真实窗口观察和工具未提供的字段。

坐标点击曾遇到几何信息问题。未形成有效点击属于工具执行问题，应保留错误和调用前窗口状态；不能把它直接记成应用没有响应。也不能仅因某个浏览器入口关闭原生能力，就断言整个会话没有独立的 Windows 桌面控制入口。先按当前 Computer Use 技能做最小窗口访问，再判断可用范围。

## Full access 与审批设置需要具体解释

清理测试文件时，包含 `Remove-Item` 与 `-Force` 的命令被 Codex 内置危险命令检查命中。当前审批模式为 `never` 时，需要审批的操作直接被拒绝，即使文件系统为完全访问。返回的 `blocked by policy` 没有说明具体规则，导致多轮解释仍不能帮助用户处理。

排查应核对实际运行配置、拒绝的原始命令与对应版本源码，不能把泛化错误猜成项目规则、用户主动设置或 Guardian 判定。相关产品提示与错误处理问题已提交 [openai/codex #45403](https://github.com/openai/codex/issues/45403)。用户切换到 `Ask for approval` 后，针对两份测试文件的审批和清理已完成。

另一次自动审批遇到审核模型不可用，属于审批服务故障。必须如实说明失败发生在审核服务，不能误报为用户缺少文件权限或未经授权。遇到明确拒绝不应通过替换删除工具来绕过；应提供原始拒绝理由，并使用受支持的审批路径处理。

## 长期排查与回归入口

- 应用动作、目标校验和状态查询：`src/app/actions.rs`。
- 使用真实工作线程的确定性无界面场景：`src/app/action_scenario.rs`。
- Shell 菜单身份、冲突窗口收尾和对应回归测试：`src/app.rs`。
- 控件语义测试：`src/accessibility_tests.rs`；UI 定义：`ui/app-window.slint`、`ui/quick-menu.slint`。
- 完整验证：`python tools/verify.py`；机器可读结果：`artifacts/verify/summary.json`。
- 应用层操作证据：`artifacts/state/agent-actions/sequence.json`；真实窗口报告与文本树：`artifacts/ui/issue-111-live/`。

后续验收优先设计小文件、可等待、可查询终态的场景；每个结论应能对应到真实操作、状态或文件结果。用户已授权的工作由 Agent 完成，确需用户参与时应给出具体操作及其解决的阻塞，避免只报告“不能继续”。
