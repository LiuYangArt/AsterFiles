# Postmortem：#93 普通点击被误判为文件拖放

用户确认 Debug 中双击 Bridge 进入后使用侧键返回，Bridge 实际出现在 Whitebox 内。既有窗口日志没有文件操作来源、目标和结果，不能认定本次事件的唯一根因。

## 已实证的危险路径

Slint 1.17.1 在左键释放时先执行 clicked，再清除 pressed，最后发出 Up。无窗口测试证明：在 clicked 中下移父控件 40 像素，同位置释放的坐标计算从 20 变为 60。旧列表 Up 又要求 pressed 为真，因此无法正常清理；旧网格重新计算控件坐标。旧结束回调未要求任何 Move，仅凭至少 4 像素距离就从当前页面命中目标并直接创建文件操作。

## 修复决策

删除控件释放直接投放的路径及其命中代码。原生窗口按下记录固定坐标，Slint 只绑定稳定条目，原生移动消费一次候选后进入现有 OLE。候选校验标签、请求及原始路径；释放和上下文变化取消。原生 Drop 也必须消费 DragEnter 创建的来源快照，取消、重复投放或来源替换不能提交。

## 回归与后续排查

`cargo test issue_93` 覆盖输入顺序、布局位移、实际列表/网格模型重建、取消和身份校验。`cargo test native_file_drop` 以无窗口 COM 和内存数据验证零/一次投放及效果协商。`cargo test operation_audit` 用临时目录验证有序追加与退出排空；这些检查也包含在统一快速验证中。

`artifacts/verify/summary.json` 是最终验证结果。`artifacts/logs/file-operation-audit.jsonl` 按 PID 和时间记录 navigation、drag_armed、drag_cancelled、drag_ole_started/finished、native_drag_enter/leave/drop/reject、drop_dispatch、operation_enqueued/started/finished。排查时先找到任务结果，再向前核对来源、目标、标签/请求和原生投放，不用窗口点击日志推断实际文件操作。

真实桌面拖动与鼠标侧键由用户在临时目录验收。所有自动测试均禁止操作用户工作目录；修复不会恢复或移动既有 Bridge 数据。


## 经验与预防

- 不用控件的结束位置推断用户曾经拖动。释放期间的导航、布局刷新与控件重建都可能改变坐标；文件操作授权必须来自独立、可消费一次的系统拖放生命周期。
- 不假设 UI 框架的事件顺序。先检查实际依赖版本源码，再用无窗口测试验证 pressed、clicked、Up 的先后与布局影响。清理不能依赖框架已经清除的 pressed 状态。
- 来源身份与投放权限分开校验：固定原始路径和标签/请求，失效即取消；Drop 先消费再检查，失败也不能重复使用旧上下文。
- 输入日志不能替代文件操作审计。关键日志应默认持久保存来源、目标、任务结果与时间，才能区分用户导航、合法拖放和实际磁盘修改。
- 对数据安全事故保留证据边界。无窗口测试证明漏洞成立，不等同于证明历史事件走过该路径；没有完整日志时不得把推测写成唯一根因。
- 回归包含真实框架回调与原生 COM 的内存测试，同时保留用户对真实鼠标交互的验收；不得用真实工作数据自动复现。
