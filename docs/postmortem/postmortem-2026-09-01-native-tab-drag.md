# P4 原生标签拖动与插入指示器复盘

日期：2026-09-01

影响范围：Windows 标签同窗排序、拖出新窗口、跨窗口移动及落点提示

状态：已修复并由用户确认核心拖动与指示器可用

## 摘要

P4 标签拖动先后出现卡片被来源窗口裁切、第一次拖不动、标签完全无法拖动、窗外禁止光标，以及插入指示器始终不可见。自动状态测试多次通过，但真实 Windows 交互仍失败。

最终根因不是标签状态事务本身，而是 Windows 原生拖动与 Slint/winit 绘制调度之间的边界没有一次确定清楚：跨窗口手势需要 OLE 接管；`IDragSourceHelper` 会向数据对象写入 Shell 私有介质；`DoDragDrop` 又会同步占用当前事件回调，使 Slint 的属性更新无法在拖动过程中真正出帧。

## 用户可见症状

- 标签卡片被来源窗口客户区裁切，不能持续跟随光标。
- 第一次拖动只出现静止卡片，第二次才偶尔成功。
- 切换到 OLE 后，越过阈值立即取消，表现为完全拖不动。
- 标签离开窗口时鼠标显示禁止图标。
- 同窗与跨窗移动可完成，但标签栏看不到插入位置竖条。

## 根因

### 1. 应用内预览无法跨越原生窗口边界

Slint 场景中的拖动卡片受来源窗口裁切，也无法获得桌面级屏幕坐标和目标窗口 OLE 命中。独立轮询预览窗口又把一次手势拆成两套输入所有权，造成第一次手势停在原地。

### 2. 自定义数据对象丢弃了 Shell 私有介质

`IDragSourceHelper::InitializeFromBitmap` 会通过 `IDataObject::SetData` 写入不止一种私有介质，其中包含 `HGLOBAL` 和 GDI 介质。早期实现只按格式号保存 `HGLOBAL`，初始化因此返回错误，OLE 尚未开始就取消。

### 3. 默认 OLE 反馈把窗外解释为禁止目标

标签拖出所有已注册目标时，系统默认反馈根据 `DROPEFFECT_NONE` 显示禁止光标；但 AsterFiles 的产品语义是窗外释放可创建新窗口，因此标签拖动必须单独保持普通箭头，同时不改变文件拖放的复制、移动和链接反馈。

### 4. `request_redraw` 不能突破模态 OLE 循环

`DoDragDrop` 在 Slint/winit 输入回调中同步运行。OLE 期间属性写入和 `request_redraw()` 都成功，但 winit 只能缓存重绘，真正的 Slint/Skia 绘制要等 `DoDragDrop` 返回。因此放在 Slint 树中的插入竖条在拖动过程中必然不可见。

## 最终修复

- 标签拖动统一使用 Windows OLE 私有格式和 `IDragSourceHelper` 原生卡片；来源、目标、取消和释放由一次拖动循环收口。
- 自定义数据对象保留完整 `FORMATETC`，并用系统 `CopyStgMedium` 复制 Shell 写入的介质。
- 标签拖动单独提供普通箭头反馈；文件拖放继续使用系统反馈。
- 插入指示器使用独立的 5px Windows 工具窗口，由 OLE Hover 直接更新物理屏幕位置，不依赖 Slint 出帧。
- 指示器不激活、不接收输入、不注册 `IDropTarget`，并返回穿透命中；离开、失败、取消、完成或应用清理时隐藏或销毁。
- 单文件标签窗口继续使用同一 OLE 会话：命中另一标签栏时事务式合并；窗外释放按抓取偏移移动原窗口，避免创建等价新窗口。

## 清理

- 删除已失去生产消费者的 Slint 插入指示器、跨窗投影属性和回调。
- 删除只服务旧 Slint 预览的标题、图标、抓取偏移等镜像状态。
- 删除 OLE 模态循环中无效的 `request_redraw()` 调用。
- 保留 Rust 状态层的插槽计算作为唯一落点真源；原生窗口只负责显示该结果。
- 复用同一个原生指示器窗口，并在切换目标窗口时更新 owner，避免每次 Hover 创建窗口。

## 验证与边界

- 自动测试覆盖拖动阈值、同窗排序、跨窗事务、取消、单标签合并/原窗移动分流、DPI 抓取偏移和原生拖动卡片初始化。
- `python tools/verify.py` 继续覆盖 Clippy、测试、无界面场景和 Debug 构建。
- 用户已在真实 Windows 窗口确认标签拖动、跨窗移动和原生插入指示器可用。
- 自动测试仍不能替代 OLE 模态循环中的真实视觉与输入验收；Codex 不自动操作 AsterFiles UI。

## 防复发规则

1. 桌面级拖动只有一个输入所有者；不得再叠加 Slint 指针捕获、轮询和 OLE 三套状态机。
2. Shell 调用 `IDataObject::SetData` 时保留完整格式描述和介质类型，不按单一 `HGLOBAL` 假设实现。
3. 进入同步 Windows 模态循环前，先判断框架的绘制与事件回调能否重入；不能重入时，实时视觉必须由该原生循环可驱动的表面承担。
4. 原生拖动浮层不得参与命中、焦点、拖放注册或会话恢复，并必须有明确的隐藏和销毁路径。
5. 自动测试通过只证明状态和接口契约；跨窗口命中、拖动卡片、光标和落点提示必须由真实窗口确认。
6. 用户确认某条真实交互可用后，立即删除探索阶段的镜像状态和无效兼容路径，避免两套真源长期并存。
