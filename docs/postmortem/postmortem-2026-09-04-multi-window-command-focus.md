# Issue #41 多窗口命令与菜单焦点复盘

日期：2026-09-04  
影响范围：多窗口文件命令、异步操作归属、快速菜单焦点恢复  
状态：已修复，用户已完成真实双窗口验收

## 摘要

两个 AsterFiles 窗口同时打开时，文件命令偶尔会读取另一个窗口的状态；路径路由修正后，又暴露了操作完成刷新和快速菜单关闭导致活动窗口切换的问题。自动测试一度通过，但用户在“先使用 Windows 新建子菜单，再使用 AsterFiles 新建文件夹”的真实事件序列中仍能稳定提高复现概率。

最终修复把文件命令的来源窗口、标签和路径快照贯穿到异步完成边界；界面刷新按明确窗口投影，不再临时改写共享活动窗口；原生菜单只在前台仍属于自身窗口链时恢复 owner 焦点；重命名完成只修改来源窗口，永久删除确认与右键拖放保留原始标签。

## 用户可见症状

- 在窗口 A 按 Delete，可能处理窗口 B 的选中项。
- 在窗口 B 新建文件夹，路径正确但窗口 A 偶发成为活动窗口。
- 先执行 Windows 菜单“新建 → 文件夹/文本文档”，再执行 AsterFiles 的“新建文件夹”，活动窗口切换更容易出现。

## 根因

### 1. 窗口作用域在辅助入口被隐式丢失

窗口回调持有 `WindowSessions`，但部分文件命令接收共享状态。自动解引用使调用可以静默降级，随后通过全局 `active_window` 推断标签、选择和目标目录。后台预热或延迟回调只要读取另一个窗口，就可能改变后续命令目标。

### 2. 异步请求没有完整保留来源身份

剪贴板读取、拖放选择、永久删除确认和重命名曾在异步返回或用户确认时重新读取“当前标签”。这时用户可能已经切窗或切标签，导致任务来源、刷新目标和实际路径快照不一致。

### 3. 全窗口刷新曾临时改写共享活动窗口

为投影窗口 A/B，刷新逻辑先修改全局 `active_window`，刷新后再恢复。操作完成事件触发全窗口刷新时，中间状态对其他回调可见，形成偶发活动窗口漂移。

### 4. 快速菜单无条件恢复 owner 焦点

根菜单或子菜单关闭会调用 Windows 前台激活接口。系统 Shell 子菜单增加了异步失焦和延迟关闭的窗口，使旧窗口菜单事件可能在另一个窗口已活动时恢复旧 owner。与此同时，命令完成逻辑把新建文件夹和重命名共同当作“关闭重命名编辑器”，并修改启动时绑定的初始窗口 UI，进一步放大了竞争。

## 修复

- 文件命令从触发窗口取得明确 `TabId` 和原始路径快照，再提交共享任务中心。
- 粘贴请求与返回、拖放准备与右键选择、永久删除确认均保留原始标签。
- 重命名目标按窗口保存；完成或失败只更新来源窗口的编辑状态。新建文件夹完成不再触碰重命名界面。
- 窗口投影直接读取指定 `WindowId`，不再通过切换共享活动窗口渲染。
- 快速菜单关闭前检查当前前台窗口是否仍属于该 owner/popup 链；只有匹配时才能恢复焦点。迟到的旧窗口事件不能抢占新活动窗口。
- `$code-simplifier` 收尾审查合并了重命名和删除的重复状态读取，并补齐永久删除、右键拖放及重命名完成的来源边界。

## 防复发规则

1. 文件命令在触发时必须固定 `WindowId + TabId + 原始路径/条目 ID`；异步阶段不得重新猜测当前窗口。
2. 全局 `active_window` 只描述真实活动窗口，不得被后台预热、渲染或批量刷新临时借用。
3. 共享确认窗口可复用视觉实例，但待处理数据必须携带来源标签；确认时消费快照，不读取当前窗口。
4. 原生 popup 只能在前台仍属于自身 owner 链时恢复焦点；迟到关闭事件不得调用前台激活。
5. 操作完成后的窗口级 UI 收尾必须按任务来源定位；不同命令不能因共用完成分支而修改无关编辑状态。
6. 自动测试必须覆盖“触发后切窗/切标签再返回”的延迟序列；真实 Windows 焦点与 Shell 子菜单仍需人工验收。
