# P0 快捷键与鼠标多选失效复盘

日期：2026-08-28
影响版本：P0 任务清单首次标记完成至修复提交 `fe90310` 及其后的多选修复之前
状态：已修复并加入回归约束

## 摘要

P0 任务清单把窗口快捷键和 Windows 风格多选标记为完成，但真实 Release 测试发现两者均不可用。快捷键定义存在，却放在收不到窗口按键的 Slint 焦点域中；第一次修复只调整焦点结构，仍未通过真实窗口验证。鼠标多选的领域逻辑也已存在，但界面点击没有传递 `Ctrl`、`Shift` 状态，所有点击最终仍按单选处理。

## 用户可见症状

- `Alt+Left`、`Alt+Right`、`Alt+Up`、`F5`、`Ctrl+R`、`Ctrl+L`、`Alt+D`、选择键等全部无效。
- 第一次声称修复后，用户实际测试仍无效。
- `Ctrl+单击` 不能切换离散项目，`Shift+单击` 不能选择连续范围。
- 文件与文件夹的鼠标多选行为均与 Windows 文件资源管理器不一致。

## 根因

### 1. 窗口快捷键错误依赖 Slint 控件焦点

快捷键放在尺寸为零、未进入有效焦点链的 `FocusScope` 内。定义和 Rust 回调虽然齐全，但按键事件根本没有到达这些绑定。

### 2. 首次修复缺少真实交互验证

第一次修复将焦点域扩大并设置 `forward-focus`，只通过编译和单元测试便判定完成。现有测试覆盖领域状态，不会模拟 Windows 窗口事件和真实焦点路由，因此无法证明快捷键可用。

### 3. 鼠标点击丢失修饰键

行点击回调只传递项目 ID，Rust 端固定调用普通单选。已有的切换与范围选择逻辑从未收到 `Ctrl`、`Shift` 组合。

### 4. 窗口级鼠标补丁作用对象错误

旧代码在窗口层看到 `Ctrl+左键` 后切换“当前焦点项”，而不是用户实际点击的行。它既不能实现多选，还可能修改错误项目。

### 5. 完成状态缺少端到端证据

任务清单依据“代码路径存在”和单元测试通过就标记完成，没有保留真实 Release 的按键、鼠标组合操作结果。

## 修复

- 窗口级快捷键改由 winit 原生窗口事件统一分发，不再依赖 Slint 控件焦点。
- 地址栏内部的输入按键仍由地址栏控件处理，避免破坏文本编辑。
- 行指针事件把 `Ctrl`、`Shift` 状态与项目 ID 一并传给选择逻辑。
- 删除窗口层错误的 `Ctrl+左键` 焦点切换。
- 支持普通单击、`Ctrl+单击`、`Shift+单击`、`Ctrl+Shift+单击`，文件与文件夹使用同一规则。
- `Ctrl+Shift+单击` 将锚点到目标的连续范围并入已有离散选择，并保持原范围锚点。
- 选择变化只更新前后选中集合及焦点涉及的行，不重建完整文件模型。

## 防复发规则

1. “已实现快捷键”必须在真实 Release 窗口逐项按键，不能以绑定代码存在或编译通过代替。
2. 窗口级快捷键统一走 winit 入口；控件级文本编辑键留在对应 Slint 控件内。
3. 鼠标选择必须验证普通、`Ctrl`、`Shift`、`Ctrl+Shift` 四种组合，并同时覆盖文件和文件夹。
4. 指针操作必须把实际命中项目和当次修饰键作为同一意图传递，禁止在窗口层猜测焦点项。
5. 选择锚点、焦点、选中集合是三个独立状态；组合操作不得意外重置锚点。
6. 高频选择操作只更新状态发生变化的行，不调用全量 `refresh_ui`。
7. 任务清单只有在 Release 端到端测试后才能标记完成；验证结果与可执行文件哈希一起交付。
