# 亮色主题悬浮滚动条回归复盘

日期：2026-08-28
影响范围：自定义标题栏基础版之后的本地 Release 构建
状态：已修复

## 摘要

应用主体已经固定为亮色，但文件列表右侧仍显示接近黑色的悬浮滚动条。第一次修复仅在程序启动前设置 Slint 的全局亮色样式，面包屑位置得到修正，但用户实际悬浮滚动条时仍能看到暗色轨道和滑块。

最终不再依赖系统或组件主题推导：关闭文件列表内置滚动条，在列表之上放置明确配色的轻量滚动条，并继续复用列表原有的滚轮、虚拟化与滚动位置。

## 用户可见症状

- 亮色窗口中，文件列表滚动条悬浮后变成黑色。
- 暗色滚动条与白色列表、浅灰边框明显不协调。
- 静止时滚动条较窄，若只看普通截图不容易发现；必须把鼠标移到滚动条区域才会暴露问题。

## 根因

### 1. 把全局亮色样式误当成确定性覆盖

启动前设置 `SLINT_STYLE=fluent-light` 只能选择 Slint 的总体控件风格，不能保证 Windows 上内置 `ListView` 悬浮滚动条的所有状态都使用应用期望的颜色。该滚动条仍可能受组件内部样式、系统状态或后端实现影响。

这里的需求不是“跟随当前主题”，而是“当前应用只有亮色界面，滚动条必须明确保持亮色”。继续调整全局主题无法给出稳定保证。

### 2. 验证没有覆盖悬浮状态

第一次验证主要检查了应用启动、普通界面截图和构建结果。滚动条的错误颜色只在鼠标进入滚动区域后明显出现，静态截图没有覆盖该状态，因此得出了错误结论。

### 3. 修复层级选错

问题只发生在文件列表滚动条，第一次修复却修改了应用级主题。这扩大了影响范围，同时没有直接控制真正出错的部件。更稳妥的边界是只替换文件列表滚动条，并保留列表本身的成熟滚动与虚拟化行为。

## 修复

- 文件列表禁用内置垂直滚动条。
- 新增显式亮色的轻量滚动条：
  - 默认使用 3px 浅灰滑块；
  - 鼠标悬浮时扩展到 6px；
  - 悬浮轨道使用浅灰背景；
  - 拖动时同步更新 `ListView.viewport-y`。
- 保留 `ListView` 原有滚轮滚动、内容虚拟化和滚动位置计算。
- 启动时仍设置 `fluent-light`，用于其他原生控件与当前亮色界面保持一致，但不再把它视为滚动条颜色的唯一保证。
- 同一批修改将面包屑区域上下各增加 3px 内边距，使内容垂直居中。

## 防复发规则

### 主题与控件样式

1. 固定亮色界面中的关键控件必须有确定性配色；不能只凭系统主题或全局样式变量推断最终效果。
2. 只修改出现问题的组件边界。局部视觉问题优先局部解决，避免用应用级开关碰运气。
3. 自绘滚动条不得替换列表数据、滚轮处理和虚拟化，只负责呈现及拖动位置映射。
4. 如果未来增加暗色主题，滚动条颜色必须来自统一调色板，不能继续散落硬编码颜色。

### 交互状态验证

1. 滚动条必须检查：静止、悬浮、拖动、滚轮滚动、列表顶部和底部。
2. 按钮必须检查：普通、悬浮、按下、禁用。
3. 标签必须检查：普通、悬浮关闭按钮、中键关闭、最后一个标签不可关闭。
4. 视觉问题的验收截图必须包含触发问题所需的鼠标状态；普通静态截图不能替代悬浮验证。
5. 必须运行用户实际使用的 Release 程序，不能仅凭 Debug 或编译通过判断视觉结果。
