# AsterFiles UI 与交互设计

> 状态：P0 交互已确定；P1 范围与实施原则已确定，具体视觉数值随实际效果调整
> 范围：Windows 桌面端本地文件浏览、视觉系统与基础设置
> 参考：Files 本地源码 `F:\CodeProjects\Files`，基准提交 `abdfcb543adc7fcdf7f75672feb83760c48d9087`，以及用户提供的 Files 深色界面截图  
> 原则：参考成熟产品的结构与交互规律，不复制完整界面，不把后续功能伪装成可用控件

## 1. 目标与边界

AsterFiles 的 UI 首先服务于可靠、连续的本地浏览。P0 完成后，用户应能：

- 通过侧栏、地址栏、面包屑和文件列表进入任意可访问目录；
- 使用后退、前进、向上和刷新连续导航；
- 用鼠标或键盘完成一致的选择与打开；
- 清楚分辨加载、空目录、无效路径、权限不足、读取失败和位置断开；
- 在窄窗口、高 DPI、浅色和深色环境中辨认路径、焦点和选中项。

从 Files 借鉴：顶部导航、地址栏、命令区、侧栏、详情列表、状态栏的层级；面包屑/路径输入双态；扩展选择；语义化图标；原位置反馈。

不照搬：标签页、命令面板、搜索、云盘、标签、预览、多布局等超出 P0 的功能；不把 Files XAML 逐层翻译为 Slint；不复制来源不明的侧栏 PNG；不在 UI 中访问磁盘或 Shell。

## 2. 总体结构与阶段

```text
窗口
├─ 标签区（基础能力已由 F3 建立）
├─ 导航区
│  ├─ 后退、前进、向上、刷新
│  └─ 地址栏：面包屑显示态 / 智能编辑搜索态
├─ 工作区
│  ├─ 侧栏
│  └─ 主内容
│     ├─ P0 命令区：选择、排序
│     ├─ 详情列表或页面状态
│     └─ 状态栏
└─ 浮层：工具提示、历史菜单、局部错误说明
```

- **P0**：沿用 F3 已建立的多标签基础；每个标签拥有独立路径、历史、列表、加载和错误状态。P0 只完善浏览交互，不扩展标签拖动、复杂菜单等效率功能。
- **P1**：在同一结构上完成浅色/深色、高 DPI、字体、图标和统一视觉变量。
- **P2**：加入真实可用的新建、剪切、复制、粘贴、重命名、删除等操作。
- **P4**：完善标签拖动排序、关闭恢复和会话体验，并加入布局、过滤、预览等入口。

F3 已完成多标签基础，P0 不拆除或降级现有能力。标签区、导航区和页面内容保持独立；所有 P0 状态继续归属各自标签，P4 只增强标签交互而不重写导航和列表。
### 2.1 P1 实施原则

P1 先整理现有实现，不在文档中预设一套未经界面验证的视觉数值：

- 按钮、文字、面板、列表状态、边框和图标尺寸统一从共享样式入口读取；首轮保持当前浅色界面的实际效果，再根据可见结果调整；
- 标题栏左侧增加菜单按钮，菜单提供设置入口；设置页首期只承载主题和语言，不提前扩展其他配置；
- 主题提供“跟随系统、浅色、深色”。跟随系统在应用启动时读取；用户选择可覆盖并保存。本阶段不实时响应系统主题变化，不做高对比度模式；
- 主题作用于整个应用。切换深色时，自定义标题栏和其他区域一样改为深色背景、浅色文字，并同步调整边框、图标和悬停、按下、禁用、焦点、选中状态；
- 语言切换从侧栏移入设置页；
- 视觉验收以实际运行效果为准，由人工检查浅色、深色、常用缩放及窗口尺寸，不用预设数值代替肉眼判断。

## 3. P0 页面布局

### 3.1 窗口标题区

- 采用自定义标题栏基础版，标签与窗口控制同排；不再显示应用名称文字 Logo。具体交互见 [custom-titlebar-basic.md](custom-titlebar-basic.md)。
- 建议尺寸 `1180 × 760`，最小尺寸 `820 × 520`。
- 保留已可用的新建、切换、关闭和恢复标签；未实现的拖动排序、复杂右键菜单不显示占位入口。
- 窄窗口优先压缩地址栏和次要列，不把文件名列压到不可识别。

### 3.2 导航区

从左到右固定为：侧栏开关（需要时）、后退、前进、向上、刷新、地址栏。P0 不放全盘搜索。

- 高度基线 `48px`；图标按钮热区不小于 `36 × 36px`；
- 按钮只显示图标，悬停提示同时显示名称和快捷键；
- 无历史时禁用后退/前进；根目录禁用向上；加载中禁用刷新；
- 窄窗口保留后退和地址栏，前进、向上、刷新按顺序收入“更多”；
- 不用文字箭头、Emoji 或字体文件图标代替正式图标。

### 3.3 地址栏

地址栏包含互斥的两个状态。

**面包屑显示态**

- 默认显示，每段代表真实路径节点；单击父级导航，单击当前节点不重复加载；
- 空间不足时从左折叠祖先节点，当前目录始终可见；
- 根目录显示磁盘图标与卷标，不统一写成“Home”；
- 面包屑文本只用于显示，真实路径仍由应用层 `PathBuf` 保存。

**智能编辑搜索态**

- 单击地址栏空白、`Ctrl+L`、`Alt+D` 调用同一个入口，预填“当前完整路径 + 一个空格”，不全选，光标位于末尾；
- 保留完整前缀时，输入内容搜索当前目录及子目录；删除完整前缀后切换为全局搜索；
- `Enter` 先在后台判断完整输入：有效路径导航，其余内容交给 Everything 搜索；`Escape` 取消并恢复已成功路径；
- 路径范围与用户查询独立保存，不按空格拆分，地址刷新不得用查询覆盖组合后的显示文本；
- 无效路径或搜索错误不清空旧历史，结果严格受标签、请求和页面来源隔离。

### 3.4 侧栏

P0 只分两组：

- **常用位置**：主页、桌面、下载、文档、图片、音乐、视频；
- **磁盘**：系统当前实际存在的本地磁盘。

规则：

- 默认展开；组标题可折叠；行高 `32px`，图标 `16px`；
- 选中态使用背景色和左侧强调条；单击直接导航；
- 当前路径位于磁盘深层时，磁盘项保持归属选中，不展开完整目录树；
- 数据必须从系统读取，不保留写死演示项；磁盘变化时刷新；
- P0 不显示云盘、网络、标签和回收站，除非已有真实数据和完整打开行为；
- 收藏、拖动排序放到 P4。

### 3.5 命令区

P0 只呈现已实现能力：

- 选择：通过行点击、`Ctrl` / `Shift` 与 `Ctrl+A` 完成，不单设“全选/清除选择”按钮；
- 排序：单击名称、类型、大小、修改时间列标题切换升序/降序，当前排序列显示方向；
- 当前排序字段和方向必须可见；列标题也调用同一排序命令；
- 不显示“新建”、剪切、复制、粘贴、分享、删除、属性等灰色占位按钮。

### 3.6 文件详情列表

P0 固定详情列表，列顺序为：图标与名称、类型、大小、修改时间。

- 名称列优先伸缩；文件夹大小为空，不显示 `0 B`；
- 文件夹始终位于文件之前，各自按当前字段和方向排序；
- 列标题可排序，当前列显示方向标记；
- 行高 `36–40px`，图标 `16–20px`；长名称尾部省略，悬停显示全文；
- 列表必须虚拟化，不一次创建全部行；
- 图标后台替换不得改变滚动位置；进入新目录后回到顶部。

鼠标行为：

- 单击只选中；`Ctrl+单击` 切换单项；`Shift+单击` 从锚点扩展；连续两次点击同一项按 Windows 系统双击间隔打开，不依赖窗口原有焦点；
- 双击文件夹进入目录；双击文件交给 Windows 默认应用；
- 单击空白处清除选择；右键系统菜单留到 P3。

键盘行为：

- 方向键移动焦点，`Shift+方向键` 扩展范围；
- `Ctrl+Space` 切换焦点项，`Enter` 打开；
- `Ctrl+A` 全选，`Escape` 先退出地址编辑或清除选择；
- `Home/End` 移到首项/末项；
- 鼠标和键盘调用同一应用命令，不维护两套行为。

### 3.7 状态栏

- 无选择显示目录项目数；有选择显示“已选择 N 项”，能快速计算时再显示总大小；
- 部分条目失败时显示“有 N 项未读取”，悬停可看说明；
- 加载中显示“正在加载…”和轻量反馈，不显示虚假百分比；
- 路径错误不能只藏在状态栏，内容区必须有明确提示。

## 4. 导航与历史

应用协调层持有唯一导航状态：当前成功路径、后退栈、前进栈、待处理请求、加载代次/取消标记、加载状态、页面错误。

所有入口统一提交导航意图：地址栏、面包屑、侧栏、打开文件夹、后退、前进、向上、启动恢复。UI 不自行判断目录、读取磁盘或直接改历史。

历史规则：

- 普通导航成功：旧路径压入后退栈，清空前进栈；
- 后退成功：当前路径压入前进栈；前进成功则相反；
- 刷新不改历史；向上视为普通导航；
- 失败或被新请求取消：不改当前路径和历史；
- 同一路径连续请求不新增历史，可转为刷新或忽略；
- 历史保存原始 `PathBuf`，显示名称按需生成。

后退/前进在 P0 支持右键历史菜单；菜单打开时临时从历史栈生成，不在 UI 长期复制历史数据。

### 4.1 快捷键

| 行为 | 快捷键 |
|---|---|
| 后退 | `Alt+Left`、鼠标后退键 |
| 前进 | `Alt+Right`、鼠标前进键 |
| 向上 | `Alt+Up` |
| 刷新 | `F5`、`Ctrl+R` |
| 智能编辑地址/搜索 | `Ctrl+L`、`Alt+D` |
| 全选 | `Ctrl+A` |
| 打开焦点项 | `Enter` |
| 取消/清除 | `Escape` |

## 5. 加载、取消与错误

### 5.1 页面状态

| 状态 | 列表 | 地址栏 | 反馈 |
|---|---|---|---|
| 初始加载 | 空白骨架 | 目标路径 | 正在加载 |
| 切换加载 | 保留旧列表，降低交互权重 | 待确认路径 | 正在打开目标目录 |
| 成功有内容 | 新列表 | 提交当前路径 | N 项 |
| 成功空目录 | 空状态 | 提交当前路径 | 此文件夹为空 |
| 路径不存在 | 保留旧列表 | 保留输入并标错 | 找不到该位置 |
| 权限不足 | 不伪装为空 | 目标路径 | 无权访问，可返回/重试 |
| 读取失败 | 不伪装为空 | 目标路径 | 可读原因与重试 |
| 位置断开 | 标记不可用 | 最后路径 | 驱动器或位置已断开 |

### 5.2 并发与反馈

- 目录读取始终在后台；每次导航递增加载代次，只有最新代次可提交 UI；
- 新导航取消旧导航，旧结果晚到必须丢弃；
- 加载中仍可后退、前进或点侧栏，不能锁死窗口；
- 重复刷新禁用，避免无意义排队；
- 列表模型只在 UI 线程更新，磁盘读取和元数据获取不在 UI 线程。

普通错误用地址栏下方或内容区顶部的局部提示，不弹模态框。提示说明问题和目标位置，提供“重试”或“返回”；系统错误码写日志，不作为默认文案。失败不能覆盖上次成功历史，必须可通过编辑地址、后退、侧栏或重试恢复。

## 6. 焦点、可访问性与响应式

- 图标按钮必须有工具提示和无障碍名称；键盘焦点必须可见；
- 选中态与焦点态分离：选中表示操作目标，焦点表示键盘位置；
- 颜色不是唯一状态表达：排序有箭头，错误有图标和文字；
- 命中区域不小于 `32 × 32px`，主要导航按钮为 `36 × 36px`；
- 正文用 Windows UI 字体及系统中文回退；图标字体不承担正文；
- 高对比度模式后置到 P5；P1 不为其增加专用实现；
- 建议 Tab 顺序：导航按钮 → 地址栏 → 命令区 → 侧栏 → 文件列表 → 状态栏交互项。

响应式：

- `≥1000px`：完整侧栏、完整导航按钮和四列详情；
- `820–999px`：缩窄侧栏和名称列，向上与刷新按钮彻底移出布局，地址框自动占用释放空间；
- 最小宽度时隐藏侧栏和前进按钮，始终保留后退、地址栏与前往按钮；
- 文件列表始终显示名称、类型、大小、修改时间四列，通过重新分配列宽适配，名称可省略显示；表头和文件行共用同一组列宽；
- 右侧滚动条控件向 14px 窗口缩放带内延伸 5px，用控件自身透明边距抵消视觉空隙；可见滑块保持在缩放带内缘附近，文件内容同步预留空间，DPI 缩放不改变逻辑命中尺寸。

## 7. 图标系统

### 7.1 三类图标分离

1. **操作图标**：后退、前进、向上、刷新、选择、排序；
2. **导航语义图标**：主页、常用位置、磁盘；
3. **文件系统图标**：文件、文件夹、磁盘、快捷方式、关联类型、缩略图。

不得用“字符串/Emoji + 字体兜底”统一承载三类图标。

### 7.2 独立语义映射

UI 只使用稳定语义名，例如：

```text
nav.back / nav.forward / nav.up / nav.refresh / nav.more
location.home / desktop / downloads / documents / pictures / music / videos
selection.all / sort.ascending / sort.descending
status.loading / status.warning / status.error
```

映射层负责解析为 SVG/path、系统字体字形或 Shell 图像，页面不直接写第三方资源路径。P0 只引入实际用到的语义。

### 7.3 来源与许可

操作图标优先级：

1. Microsoft Fluent UI System Icons 官方 SVG/path；
2. Files 中逐个确认标注 MIT 的操作图标；
3. Windows 自带 Segoe Fluent Icons / Segoe MDL2 Assets 字形，仅调用系统字体，不打包字体文件。

每个导入图标记录语义名、原始名称、来源/提交、许可证和修改情况；保留版权与 MIT 声明；检查 `16px`、`20px` 清晰度和笔画一致性。

Files 的 `Assets/FluentIcons/SidebarSections` PNG 来源和授权证据不足，P0 不复制。主页等入口使用明确许可的 Fluent SVG；磁盘最终使用 Windows Shell 图标。Shell 未接入前可用明确授权的通用磁盘占位图，但不能伪装成用户真实图标。主题图标优先使用可着色矢量或系统图标，不维护多套不透明 PNG。

### 7.4 文件系统图标边界

Shell 图标完整归 P1，并在独立的 Windows 平台模块中实现；P3 在此基础上继续扩展缩略图、右键菜单等系统集成。

- 条目保留原始路径或不可解释 ID；列表先显示通用图标；
- 系统图标在后台获取，完成后原位替换，不能阻塞目录加载或界面操作；
- 切换目录、关闭标签或退出时停止已经无用的图标工作；迟到结果只能更新原来的标签和条目，不能写入新页面；
- 已取得的通用类型图标和路径专属图标可以受控复用，避免反复询问系统；主题或文件变化后不能继续使用已经失效的结果；
- 快捷方式等特殊标记若由 Windows Shell 一并返回则保持系统结果；不在 P1 自行扩展同步状态或权限盾牌规则；
- 图标失败时继续显示通用图标，不影响列表显示。

建议目标目录：

```text
ui/
├─ icons/
│  ├─ actions/
│  ├─ locations/
│  ├─ icon-map.slint
│  └─ LICENSES.md
└─ components/
   ├─ icon.slint
   ├─ navigation-bar.slint
   ├─ address-bar.slint
   ├─ sidebar.slint
   ├─ command-bar.slint
   ├─ file-list.slint
   └─ status-bar.slint
```

本次只定边界，不创建空组件。

## 8. UI 与应用层接口

UI 只消费协调层模型：

- 导航：当前成功路径显示文本、编辑文本、是否可后退/前进/向上/刷新、加载状态、页面错误、面包屑、侧栏；
- 列表：稳定条目 ID、显示名称/类型/大小/修改时间、是否目录、图标语义或异步图像、选中/焦点、排序状态；
- UI 意图：普通导航、后退/前进/向上/刷新、提交/取消地址编辑、打开条目、修改选择、修改排序、重试。

真实 `PathBuf/OsString` 不进入 Slint 显示模型作为唯一身份。打开和后续文件操作通过条目 ID 回到应用层解析原始路径。

## 9. P0 实施切片

严格按纵向闭环推进：

1. 导航壳层：历史、后退、前进、向上、刷新、快捷键；
2. 地址栏：面包屑、编辑、提交/取消、无效路径；
3. 打开闭环：双击/Enter 进入目录，文件交给默认应用；
4. 选择闭环：单选、Ctrl/Shift、多选锚点、键盘焦点、全选；
5. 排序闭环：列标题、菜单、目录优先、方向状态；
6. 页面状态：加载、空、权限不足、不存在、失败、断开；
7. 真实侧栏：系统常用目录与磁盘；
8. 会话恢复：窗口位置、尺寸、最近目录。

每项包含行为、界面状态、错误和验证，完成后再进入下一项；不先做整套静态皮肤。

## 10. P0 验收清单

### 导航与地址

- 按钮与快捷键结果一致；根目录、快速导航和失败导航不破坏历史；
- 普通导航清空前进栈，后退/前进不重复记历史；
- 右键历史菜单可跳转，新请求能取消旧加载；
- 面包屑、地址、侧栏和列表统一入口；
- 点击空白、`Ctrl+L`、`Alt+D` 均显示“完整路径 + 空格”、不全选且光标在末尾；`Enter` 分流导航/搜索，`Escape` 取消；
- 无效路径保留输入和旧列表，错误可恢复；
- 中文、日文、韩文、Emoji 名称显示、导航、打开正确；
- 显示文本不承担文件身份，真实路径不被有损转换覆盖。

### 列表、状态与图标

- 单击、双击、Ctrl/Shift、方向键、Enter、Ctrl+A 一致；
- 选择、焦点、悬停可区分；排序字段与方向可见；
- 加载、空、权限不足、不存在、失败、断开均有独立反馈；
- 大目录不一次创建全部行，不在 UI 线程读取磁盘或图标；
- UI 不使用 Emoji、文本箭头或首字符模拟正式图标；
- 操作、侧栏、Shell 图标来源和映射分离；复制资产有许可记录；
- 人工检查浅色、深色、常用缩放和窗口尺寸，发现视觉问题时按实际效果修正；本阶段不验收高对比度模式；
- 图标失败不阻断列表。
