# P4 高频效率功能决策与实施范围

## 1. 文档目的

本文汇总 P4 的产品讨论，确定当前实施范围、交互结果、技术边界和推荐切片。后续设计与实现以本文为准；未列入当前范围的功能不提前建设兼容层或占位入口。

## 2. P4 当前目标

P4 收敛为三个相互独立的纵向功能：

1. 浏览器式多窗口标签管理；
2. 与 Windows Explorer 共享的固定目录；
3. 详细信息、列表、网格视图及 Windows 系统缩略图。

目标效果是让用户可以按工作内容拆分窗口、在窗口间整理标签、快速进入 Windows 已固定的目录，并通过系统缩略图浏览图片、视频和安装了缩略图扩展的特殊格式。

## 3. 明确不做

- 当前目录快速过滤：Everything 已覆盖当前目录、递归目录和全局搜索，不维护第二套过滤逻辑；
- 批量重命名与操作预览；
- 双栏模式；
- 预览面板：当前阶段以网格缩略图满足快速识别需求；
- 全盘内容索引、网络协议、插件系统；
- AsterFiles 自有收藏数据库；
- 侧栏固定目录拖动排序。

## 4. 多窗口标签管理

### 4.1 功能范围

1. 同一窗口内拖动标签排序；
2. 标签拖出当前窗口，生成一个新窗口；
3. 将 A 窗口的标签拖到 B 窗口，按指针落点插入 B 的标签栏；
4. 保存并恢复多个窗口的位置、尺寸、标签归属、标签顺序和活动标签。

### 4.2 拖动视觉

开始有效拖动后：

- 指针下方显示一个与标签栏标签同尺寸、同圆角、同主题颜色的拖动卡片；
- 卡片内显示原标签的图标和名称，文字裁剪规则与普通标签一致；
- 卡片跟随指针移动，并保持稳定的相对抓取位置；
- 来源位置的原标签暂时隐藏，其他标签收拢并显示当前插入位置；
- 进入另一个 AsterFiles 窗口的标签栏时，该窗口显示明确的插入空位；
- 拖出所有现有窗口的标签栏后继续显示卡片，并在有效释放时创建新窗口；
- 按 Escape、失去有效目标或拖动被系统取消时，卡片消失，原标签恢复。

拖动卡片只表达标签，不使用文件拖放的复制、移动或快捷方式反馈，也不复用文件拖放菜单。

### 4.3 转移语义

“关闭来源页面，在目的地创建新页面”作为用户可见语义是合理的，但实现采用先接收、后删除的事务式交接：

1. 拖动开始时，来源标签暂时隐藏，但其页面、导航状态和后台身份仍保留；
2. 目的窗口先成功创建目标标签壳层，并接收原始路径、前进/后退历史、视图状态等可转移状态；
3. 目的标签准备成功后，来源窗口才真正移除原标签；
4. 如果目标创建失败、窗口关闭、拖动取消或释放位置无效，来源标签原位恢复；
5. 任意时刻不能同时出现两个可操作的同一标签，也不能出现来源已删除而目标尚未建立的空档。

正在加载、搜索或等待图标回填的标签在转移时取消旧请求，由目的窗口生成新请求并重新加载。已完成目录可以转移只读快照，避免不必要的重新枚举；所有后续结果仍按新的窗口归属和请求身份校验。

### 4.4 默认产品规则

- 标签身份在整个应用进程内全局唯一；
- 同窗排序和跨窗插入均按指针位置确定；
- 标签移动后保留路径、导航历史、选择、排序和可安全转移的视图状态；
- 来源窗口最后一个标签被拖出后，来源窗口关闭；
- 关闭一个窗口只关闭该窗口的标签；关闭最后一个窗口才退出应用；
- 文件任务中心由整个应用共享，标签换窗或单个窗口关闭不应中断文件任务；
- 主题、语言、Everything 配置、文件显示设置和固定目录为应用级共享；
- 多窗口状态跨重启恢复；
- 设置标签首版不参与跨窗口拖动，只允许普通文件标签移动。

### 4.5 架构边界

当前单窗口状态拆成三层：

- 应用级：窗口注册表、全局窗口/标签身份分配、共享文件任务中心、共享后台工作设施、内部标签拖动会话；
- 窗口级：窗口位置和尺寸、标签顺序、活动标签、关闭标签恢复栈及窗口界面引用；
- 标签级：原始路径、导航历史、目录快照、选择、排序、搜索、加载和取消状态。

后台目录、Everything、图标和缩略图结果必须携带足以定位唯一标签归属的身份。不得依赖每个窗口各自从 1 开始的裸标签编号。

标签拖动使用应用内部的拖动协调器，不复用面向 Explorer 的文件 OLE 拖放状态。文件拖放与标签拖动拥有独立状态机和命中区域。

## 5. Windows Explorer 固定目录

AsterFiles 不维护独立收藏列表。侧栏固定目录以 Windows Shell 的 Explorer“主页/快速访问”固定项为唯一来源：

- 通过 Windows Shell 枚举固定文件夹，并读取固定属性；
- 在 Explorer 中固定或取消固定后，AsterFiles 刷新并反映变化；
- AsterFiles 的固定与取消固定操作调用 Windows Shell 能力；
- Shell 调用失败时显示明确错误，不影响目录浏览；
- Windows Shell/COM 工作集中在 Windows 平台模块，不进入 UI 线程。

当前不提供侧栏拖动排序。Windows 没有适合本项目依赖的稳定公开排序接口；通过“全部取消固定后再依次固定”模拟排序会产生破坏性中间状态和失败风险，因此不采用。侧栏顺序直接跟随 Windows Shell 返回顺序。

## 6. 视图与系统缩略图

首版提供详细信息、列表和网格。默认继续使用详细信息视图。每个目录记忆自己的视图设置；记录键使用原始路径身份。视图切换不重新枚举目录，不改变标签的导航历史和选择身份。

网格必须支持图片和视频缩略图，并统一使用 Windows Shell 系统缩略图能力：

- 优先读取 Windows 共享缩略图缓存；
- 缓存未命中时，由 Windows 调用系统已注册的缩略图扩展；
- 不自行实现图片、视频、RAW、设计文件或其他特殊格式解码；
- 用户安装相应系统缩略图插件后，AsterFiles 自动受益；
- 无缩略图、扩展失败或超时均回退到现有 Shell 类型图标；
- 缩略图按当前窗口、标签、请求和条目身份校验，迟到结果不能串页。

缩略图加载位于后台，采用可见区域优先、有限并发、可取消和受控缓存。切换目录、关闭标签、移动标签或关闭窗口时，取消不再有消费者的工作；多个窗口请求同一文件同一尺寸时可以复用缓存结果。

## 7. 推荐实施切片

1. 多窗口状态分层，保持现有单窗口行为不变；
2. 同窗标签排序，完成拖动阈值、卡片、隐藏来源、插入位置和取消恢复；
3. 拖出创建窗口，完成事务式交接、最后标签规则和失败回滚；
4. 跨窗口移动，完成目标命中、插入位置和窗口关闭竞态；
5. 多窗口会话恢复，直接升级正式会话格式，不保留旧格式迁移或回退；
6. Explorer 固定目录同步；
7. 详细信息、列表和网格的统一视图模型；
8. Windows 系统缩略图队列、缓存、取消和可见区域优先加载。

## 8. 验收结果

- 标签可在同窗稳定排序，点击、关闭和窗口拖动不被误触；
- 拖动卡片外观与真实标签一致，来源标签隐藏，取消后原位恢复；
- 标签可拖出生成新窗口，也可在两个窗口之间双向移动；
- 正在加载、搜索和回填图标时移动标签，不出现重复页面、丢失或迟到结果串窗；
- 重启后恢复窗口布局、标签归属、顺序和活动标签；
- AsterFiles 与 Explorer 显示相同的固定目录及顺序；
- 三种视图切换不重新读取目录，并能按目录恢复；
- 图片、视频和系统已安装扩展支持的特殊格式显示系统缩略图；
- 大目录滚动优先加载可见区域，无缩略图时稳定回退到类型图标。

真实窗口中的拖动手感、跨窗口命中、缩略图视觉和高 DPI 表现由用户手动验收；自动验证覆盖状态转移、身份隔离、取消、回滚、会话编码和缓存边界。
