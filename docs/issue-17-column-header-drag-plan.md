# Issue #17：详情列表列标题悬停与可视化拖动换序方案

GitHub Issue：[为详情列表列标题增加悬停与可视化拖动换序](https://github.com/LiuYangArt/AsterFiles/issues/17)

状态：已完成。代码与自动验证已通过，用户已确认真实窗口中的悬停、indicator 与拖动换序交互可用。

## 1. 背景与结论

普通目录和 Everything 搜索结果已经共用唯一的详情列表标题栏、列几何与横向滚动链路，并分别保存列顺序和列宽。当前标题栏缺少悬停反馈；拖动换序只有源列透明度变化，最终落点根据横向位移粗略换算，不能直观看到拖动对象和插入位置。

本 Issue 只改进标题栏交互和视觉，不改变目录加载、Everything 搜索、排序含义、列宽模型或会话格式。

## 2. 已确认的产品行为

### 2.1 悬停

- 鼠标进入列标题主体时，使用与文件行完全相同的悬停颜色。
- 调宽命中区继续使用调宽光标，并与标题主体显示连续背景。
- 单击仍排序；只有越过拖动阈值才进入换序，轻微移动不能吞掉排序。

### 2.2 拖动浮块

- 浮块跟随鼠标，只显示当前列名，不携带排序箭头。
- 浮块采用半透明标题卡片，尺寸以当前列标题内容为基础，但应限制最大宽度，长路径列标题不生成过宽浮层。
- 源列保持原位，不在移动过程中提交持久顺序。

### 2.3 落点指示

- 使用列之间的竖直 indicator。
- indicator 与标签页拖拽共用颜色、宽度及明暗主题样式入口，但列拖动不进入标签页的跨窗口 OLE 流程。
- 以每个可见列的几何中心为分界，指针位于中心左侧时插入该列之前，位于右侧时插入该列之后。
- 支持第一列之前和最后一列之后；indicator 必须与松开后的最终位置一致。

### 2.4 结束与取消

- 有效松开只提交一次换序；目标等于源位置时不刷新。
- `Escape`、窗口失焦、标签切换、视图切换和无效释放统一取消。
- 取消后恢复原顺序，清除浮块、indicator 和指针状态。

## 3. 状态设计

列拖动使用独立的短生命周期状态，不进入会话持久化：

- 源列稳定类型及源索引；
- 按下时的窗口内指针坐标；
- 当前阶段：已按下或正在拖动；
- 当前指针坐标；
- 当前目标插入槽；
- 当前页面使用普通列配置还是搜索列配置。

列顺序仍以现有 Rust 状态为唯一持久来源。拖动中的浮块和 indicator 只投影临时状态，不能直接修改 `column_order` 或 `search_column_order`。

## 4. 交互计算

### 4.1 拖动阈值

沿用标签页拖动的统一阈值语义。按下后移动距离未达到阈值时保持点击候选；达到阈值后取消本次排序点击，进入拖动阶段。

调宽区域继续单独拥有指针手势。其按下不得创建列拖动候选，列主体也不得抢占已经开始的调宽。

### 4.2 插入槽

根据当前视觉顺序和实际列宽计算边界，不能假设列等宽。计算时包含标题栏的横向视口偏移：

1. 将窗口内指针转换为标题列内容坐标；
2. 按当前视觉顺序累计每列真实宽度；
3. 以列中心点确定落在该列之前或之后；
4. 移除源列后再规范化目标槽，避免源列自身造成偏一位；
5. 将结果限制在 `0..列数`。

只有最终槽变化时更新 indicator 投影，避免无意义重绘。

### 4.3 提交

松开时使用“源列稳定类型 + 最终插入槽”提交，不再传 `-3..3` 相对位移。协调层根据当前页面更新普通或搜索列顺序；顺序实际变化后再刷新当前窗口并沿用现有会话保存链路。

## 5. 视觉实现

### 5.1 悬停背景

标题主体和调宽区共同使用文件行的悬停样式入口。分隔线仍位于上层，悬停背景不能遮住列分隔或排序文字。

### 5.2 半透明标题块

优先在 Slint 当前窗口内绘制浮块：

- 不启动 Windows OLE；
- 不注册新的跨窗口目标；
- 不读取文件系统或调用 Windows API；
- 浮块不参与命中，避免截断原始指针事件；
- 浅色、深色均从现有主题颜色派生，并使用固定透明度；
- 文字使用当前本地化列名，超长时省略。

### 5.3 竖直 indicator

抽出标签页与列标题共用的 indicator 视觉常量，包括强调色和逻辑宽度。标签页原生 indicator 继续用于会阻塞 Slint 绘制的 OLE 拖放；列标题 indicator 在 Slint 标题栏内部绘制。两者共用样式，不强行共用窗口实现。

列 indicator 覆盖标题栏有效高度，不改变列布局宽度；必须位于标题背景和文字之上，并被标题 viewport 正确裁切。

## 6. 架构边界

- UI 只处理指针投影、浮块和 indicator，不访问路径、磁盘、Shell、COM 或 Everything IPC。
- 普通目录和 Everything 搜索使用同一交互实现，但继续分别保存顺序与列宽。
- 表头和内容行继续消费同一列几何；临时拖动状态不得改变内容行布局。
- 拖动不得触发排序、目录刷新、搜索请求、请求代次变化或退出搜索。
- 不新增会话字段，不迁移旧格式，不增加兼容层。
- 仅详情视图具有列标题；紧凑列表与网格保持现状。

## 7. 实施切片

1. 将现有相对位移换序改为明确的源列和目标插入槽，并增加纯计算测试。
2. 增加列拖动临时状态、阈值、提交和统一取消入口。
3. 接入标题悬停背景，保持调宽命中与排序行为。
4. 增加半透明标题浮块与竖直 indicator，并共用标签 indicator 样式常量。

## 8. 自动验证

至少覆盖：

- 阈值以下仍排序、阈值以上进入拖动；
- 非等宽列按实际中心点计算插槽；
- 第一列之前和最后一列之后；
- 向左、向右、跨多列和拖回原位；
- 横向滚动偏移下的落点；
- 调宽与换序手势互斥；
- `Escape`、失焦、标签/视图变化和无效释放清理状态；
- 普通与搜索列顺序互不污染；
- 换序后列宽、排序字段和请求身份不变。

完成实现后运行：

```powershell
python tools/verify.py
cargo build
```

机器可读汇总保留在 `artifacts/verify/summary.json`。交付时报告 `target/debug/asterfiles.exe` 的修改时间和 SHA-256。用户确认 Issue 完成前不构建 Release。

## 9. 人工验收

项目规则禁止 Codex 操作 AsterFiles UI。用户需在真实窗口检查：

- 普通目录与 Everything 搜索详情列表；
- 浅色与深色；
- 默认、窄窗口、最大化窗口；
- 100%、125%、150% DPI；
- 每列悬停、单击排序、拖动换序、首尾落点和拖回原位；
- 拖动中浮块只显示列名；
- indicator 与标签页 indicator 视觉一致且和最终落点一致；
- `Escape` 与窗口失焦后无残留；
- 换序后调宽、横向滚动及重启恢复正常。
