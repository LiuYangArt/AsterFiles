# P3 Windows 文件拖放实施方案

## 1. 目标

让 AsterFiles 与 Windows 桌面、Explorer 和其他兼容文件管理器之间具备一致的文件拖放行为，并支持应用内把文件放入当前目录或子文件夹。

首版只处理有真实 Windows 路径的文件和文件夹。拖入后复用 P2 文件任务中心；拖出到 Explorer 后由目标应用执行操作。正式支持 Windows 11。

## 2. 用户行为

### 2.1 拖入 AsterFiles

- 放到列表空白处：目标为当前目录。
- 放到文件夹行：目标为该文件夹，并显示明确悬停反馈。
- 放到普通文件行：目标仍为当前目录，不允许把文件当作目录。
- 同一磁盘默认移动，跨磁盘默认复制。
- `Ctrl` 强制复制，`Shift` 强制移动，`Alt` 或 `Ctrl+Shift` 创建快捷方式。
- 拖到自身、源位置或自身子目录时显示禁止状态。
- 放下后进入 AsterFiles 文件任务中心，复用进度、冲突、取消、失败重试和受影响目录更新。
- 操作成功后自动选中并聚焦新条目；所有显示源目录或目标目录的标签同步更新。

### 2.2 从 AsterFiles 拖出

- 拖动已选中条目时传递完整选择；拖动未选中条目时先改为单选。
- 使用 Windows Shell 数据对象传递原始 `PathBuf/OsString` 身份，不从显示文字重建路径。
- 允许目标协商复制、移动或创建快捷方式；桌面和 Explorer 决定最终效果并负责自己的进度和冲突界面。
- 拖放完成后读取实际执行效果；移动成功时定向更新 AsterFiles 中的源目录。
- 用户取消或目标拒绝时不修改列表。

### 2.3 应用内拖放

- 拖到当前列表中的子文件夹等同于把选中项移动或复制到该文件夹。
- 修饰键规则与拖入一致。
- 拖动经过列表边缘时受控滚动；文件夹行悬停只高亮，不自动进入目录。
- 快速访问固定使用显式 `QuickAccessPin` 投放目标：只接受单个文件夹，并在应用协调层直接提交 Shell pin；不得进入复制、移动、快捷方式或文件任务中心。已有固定项行仍是导航目标，投放区域仅为快速访问组标题。

## 3. Windows 语义

使用标准 OLE/Shell 拖放：

- AsterFiles 作为目标时，由原生窗口注册 `IDropTarget`，接收 `DragEnter`、`DragOver`、`DragLeave` 和 `Drop`。
- AsterFiles 作为源时，创建 `IDataObject` 和 `IDropSource`，通过 `DoDragDrop` 进入系统拖放循环。
- 至少支持 `CF_HDROP`、`Shell IDList Array`、`Preferred DropEffect` 和 `Performed DropEffect`。
- 支持 `DROPEFFECT_COPY`、`DROPEFFECT_MOVE` 和 `DROPEFFECT_LINK`，实际效果由源能力、目标能力、卷关系和修饰键共同决定。
- 可使用 Shell 拖动辅助对象生成 Windows 风格拖动图像和目标反馈，但不能把它作为正确性依赖。

OLE 对象、窗口注册和消息处理集中在 `platform/windows/drag_drop`，不得散落到 Slint 页面或文件任务核心。

## 4. 架构边界

```text
Slint 命中、选择和悬停展示
              ↓ 稳定 EntryId / 目标区域
应用协调层：路径快照、允许效果、操作提交
              ↓
platform/windows/drag_drop：IDataObject、IDropSource、IDropTarget、OLE
              ↓
拖入 → P2 OperationManager
拖出 → Windows 目标应用
```

- UI 线程只处理命中和展示；不得枚举目录、读取元数据或执行复制。
- 拖动开始前，应用协调层一次性把 `TabId + EntryId` 解析为原始路径快照。
- 判断同卷、目标类型、自身/子目录关系等磁盘工作放在受控后台预检查；未完成时可显示“正在判断”，不能冻结窗口。
- 拖入提交新的窗口级 `OperationId`，不复用导航 `RequestId`。
- 文件任务产生的路径变化继续广播到所有相关标签；外部目标完成的移动至少定向刷新源目录。
- OLE/COM 对象保持线程亲和；注册、拖放循环和释放必须在兼容的 STA/窗口线程完成。

## 5. 复制、移动与快捷方式

### 5.1 效果计算

优先级如下：

1. 目标明确拒绝的效果不可使用；
2. 用户修饰键覆盖默认行为；
3. 无修饰键时，同卷移动、跨卷复制；
4. 目标不支持首选效果时，从允许效果中选择安全行为；
5. 无共同效果时显示禁止。

### 5.2 快捷方式

- 拖入 AsterFiles 并选择“创建快捷方式”时，在目标目录创建 `.lnk`，不复制源内容。
- 快捷方式创建属于 Windows 平台能力，集中在现有 Shell 模块。
- 多选时为每个源项创建独立快捷方式，名称冲突采用 Windows 风格保留两者。
- 创建后通过统一受影响目录事件加入列表并选中。

### 5.3 冲突与取消

- 拖入后的复制和移动完全复用 P2 冲突界面、按类别“全部应用”、真实进度和取消语义。
- 拖出到 Explorer 时，冲突和取消由 Explorer 处理；AsterFiles 不叠加第二套任务中心。
- 外部目标没有返回可靠执行效果时，结束后只做定向刷新，不猜测删除源项。

## 6. 交互反馈

- 拖动达到系统拖动阈值后才开始，普通点击和选择不得误触。
- 拖动图像显示主条目图标和多选数量。
- 文件夹目标显示悬停背景；空白目标显示内容区轮廓或状态提示。
- 鼠标旁显示复制、移动、链接或禁止的 Windows 风格反馈。
- 拖动离开窗口、按 `Escape`、目标拒绝或窗口失焦时清除全部悬停状态。
- 拖动期间允许切换到其他应用；不能用普通模态遮罩阻断系统拖放循环。

## 7. 首版范围外

- Outlook、浏览器或压缩软件提供的虚拟文件流（`FileGroupDescriptor` / `FileContents`）。
- 回收站、控制面板、库等无普通文件系统路径的 Shell 命名空间对象。
- 远程协议文件在拖出前自动下载。
- 跨完整性级别绕过 Windows 安全限制，例如普通权限应用向管理员窗口拖放。
- 悬停自动展开目录树、自动进入文件夹或跨标签自动切换。
- 拖放撤销。

遇到范围外数据时显示不支持或禁止状态，不静默落成临时文件，也不增加兼容回退。

## 10. 完成标准

- 用户可在桌面、Explorer 和 AsterFiles 之间双向拖放真实文件和文件夹。
- 默认效果和修饰键行为与 Windows Explorer 一致。
- 拖入操作复用 P2 文件任务中心，不出现第二套冲突或进度系统。
- 拖出由 Explorer 执行时不伪装为 AsterFiles 任务，移动后源列表会自动更新。
- 复制、移动、快捷方式和禁止状态反馈准确；取消不修改磁盘。
- 原始路径身份、UI 线程边界、多标签隔离和 COM 线程亲和均保持。
- 自动验证、Windows 11 人工矩阵、`python tools/verify.py` 和 Release 构建全部通过。
